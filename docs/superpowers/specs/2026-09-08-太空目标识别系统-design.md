## 0. 摘要

本项目重构为**双坐标系运动补偿架构 (Dual-Frame Motion-Compensated Architecture)**。

核心物理洞察：**望远镜在跟踪卫星，而不是跟踪恒星。** 因此在探测器坐标系中，目标静止、恒星拖动；在天球坐标系中，恒星静止、目标运动。系统在两个坐标系中同时探测，用两条互相独立的证据链交叉确认同一目标。

这一洞察同时修正了原有流水线中一个方向性错误，并解释了此前星点计数偏高约两个数量级的原因。

## 1. 数据事实核查 (Data Forensics)

本节所有数字均由脚本实测得出，是后续全部设计决策的依据，也是答辩时应对"原理性质疑"的第一道防线。

从 `测试图像.zip` 内此前未被解包的三个文件中恢复出关键元数据：

|---|---|---|

| NORAD / 编目 ID | 60394 | `观测信息.txt` |
| 观测 ID | 1437117414637934 | `观测信息.txt` |
| 台站经纬高 | 88.5772°E, 43.5222°N, 1790 m | `观测信息.txt` |
| 观测窗口 | 2026-03-09T21:38:34 → 21:39:33 (+0800) | `观测信息.txt` |

`说明文件.txt` 记载数据包应含 `.DAT` 定位文件（UTC 时间 + J2000 赤经赤纬 + 星等，即星等真值），但**该文件不在我们持有的压缩包内**。星等绝对定标因此改由盲板求解 + 星表匹配实现（见 §5）。

### 1.2 关键发现一：望远镜在跟踪卫星

FITS 头中 `AZIMUTH` / `ELEVATIO` 逐帧连续变化：

| 帧 | AZIMUTH | ELEVATIO |
|---|---|---|
| f00 | 88.74145° | 51.03962° |
| f05 | 89.20219° | 51.03437° |
| f20 | 96.51816° | 50.48447° |
| f35 | 103.46363° | 49.45124° |

方位角在 59 s 内扫过 14.7°，且 f00–f04 近乎静止、f05 起开始持续转动。这是**跟踪机动**，不是恒星跟踪。

三条独立证据确认：

1. **全场恒星整体位移**：f05 之后星场以约 180 px/帧 的速度整体扫过视场（网格投票法测得，见 §1.5）。
2. **存在帧内静止的亮源**：`(2231, 2104)` 处有一 flux ≈ 13000、elongation ≈ 1.1 的紧致源，在 f06→f14 期间逐帧位移仅 2–3 px，而同期整个星场移动约 180 px/帧。**这就是被跟踪的目标 QIANFAN-16。**
3. **PSF 形态**：目标近似圆形（elongation 1.02–1.20）而非拖长，符合"被跟踪物体成点像"的预期。

**对原有实现的影响**：`combat_mission.py:153` 的判据

```python
target_type = "STAR" if speed < 0.5 else "DEBRIS"
```

在本数据集上**方向完全相反**——帧内静止者才是空间目标，高速运动者是恒星。这是必须修正的原理性错误。

### 1.3 关键发现二：现有星点计数约 90% 是噪声

曝光仅 30–40 ms，星场本就稀疏。实测底噪：背景中位数 5 ADU，σ ≈ 3.45，无饱和像素（最大值 26975 < 65535）。

以"真实恒星必然在下一帧复现、噪声不会"为判据做交叉验证（已补偿帧间位移，匹配半径 2 px）：

| 阈值 | 检出数 | 次帧复现率 |
|---|---|---|
| 2.0σ, npix=5 | 5922 | **9.8%** |
| 2.5σ, npix=3 | 5999 | 11.8% |
| 3.0σ, npix=3 | 806 | 35.2% |
| 5.0σ, npix=5 | **124** | **90.3%** |

结论：低于 3σ 的"检出"绝大多数是噪声涨落。

因此仓库现存产物不可用于提交：
- `master_catalog.json` 声称 `confirmed_stars: 263822`、`eliminated_noise: "100%"`
- SExtractor 基准每帧约 9021 条

两者均以 2σ 量级阈值运行，虚警占主导。按评审标准，"星点星等数据准确"是科学性 15 分的核心，且专家每提一次未被说明的原理性质疑即扣分——提交 263822 这一数字风险极高。**单帧真实星点量级为 10² 颗（f00 在 5σ/npix5 下实测 124 颗，视帧与阈值在 100–250 之间）**，并附可复现性曲线作为论证（用户已确认采用此口径）。最终提交数字以指定帧的实际测量为准，本文档不预设具体值。

### 1.4 关键发现三：热像素

`(244, 3174)`、`(312, 3206)`、`(327, 3210)` 三处在全部 36 帧中数值几乎恒定（如第一处：f00 = 305, f35 = 309），位移恒为 0.0 px。

这是**传感器热像素/坏点**，不是天体。它们对本项目有双重意义：
- 现有跟踪器会把"完美静止"当作高置信度轨迹，将其误判为目标——必须屏蔽。
- 修正后的架构以"帧内静止"作为目标判据，热像素恰好是该判据的主要混淆源，**必须在时序判决前剔除**。

副产品：热像素图本身是创新赛项的一项有效分析数据（传感器健康度评估）。

### 1.5 关键发现四：配准需要旋转

帧间变换用"旋转 + 平移"网格投票测定（已屏蔽热像素，取最亮 150 源）：

| 帧对 | 最优旋转 | 平移 (px) | 内点数 |
|---|---|---|---|
| f00→f01 | +0.0° | (+2, −2) | 134/150 |
| f06→f07 | +0.4° | (−182, −14) | 64/143 |
| f12→f13 | +0.4° | (−178, −22) | 108/142 |
| f20→f21 | +0.4° | (−178, −34) | 101/146 |
| f30→f31 | +0.3° | (−170, −46) | 61/129 |

存在约 0.3–0.4°/帧 的场旋转，与地平式 (alt-az) 机架的视场旋转特性一致。**纯平移配准会导致叠加涂抹**，配准模型必须包含旋转。

（注：全帧相位相关法在此数据上失效——它锁定到逐帧完全相同的热像素上，给出恒为 (0,0) 的伪峰。这也从反面印证了热像素屏蔽的必要性。）

### 1.6 派生量：像元比例尺

由机架转动率与实测场移量互推：

- 天球角速度 ≈ Δaz × cos(el) = 0.48°/帧 × cos 51° ≈ 0.30°/帧
- 实测场移 ≈ 180 px/帧
- **像元比例尺 ≈ 0.30° × 3600 / 180 ≈ 6 arcsec/px**
- **视场 ≈ 4096 × 6″ ≈ 6.8°**

这是一个宽视场系统。两点推论：
1. 6.8° 视场内 30 ms 曝光只能记录到 10² 量级的恒星，与 §1.3 的实测数量**独立吻合**——两条互不依赖的推理指向同一结论，这是答辩时的有力论据。
2. 宽视场使盲板求解容易成功（Tycho-2 亮星密度足够），无需深场星表。

### 2.2 为什么是双坐标系

单一坐标系只能给出一条证据。双坐标系给出两条**互相独立**的证据：

| | 探测器坐标系 | 天球坐标系 |
|---|---|---|
| 目标表现 | 静止 (< 3 px/帧) | 快速运动 (~180 px/帧) |
| 恒星表现 | 快速拖动 | 静止 |
| 热像素表现 | 静止 (混淆源) | 快速运动 (混淆源) |
| 噪声表现 | 不复现 | 不复现 |

单看任一坐标系，热像素都会与目标混淆。但热像素在**两个**坐标系中的行为与目标完全一致，唯一区别是它锁定在固定像素上且数值恒定——因此以"跨帧数值恒定性"为独立判据即可完全分离（§3.1）。

真实目标必须同时满足：探测器系静止 **且** 天球系运动 **且** 非像素锁定。三条件合取，误报率极低。

### 2.4 运行环境策略

按用户决定：**CPU 为默认路径，GPU 为可选加速。**

- 全部算法以 numpy / scipy / astropy / photutils 实现，纯 CPU 可完整跑通。
- 背景建模等热点提供 CuPy 后端，运行时探测可用性后自动启用；`import cupy` 失败即静默回退。
- 后端选择在日志中显式记录，两条路径的数值结果一致性由单元测试守卫。

理由：国赛需现场提交并运行程序，评委机器很可能无 CUDA。现有 `gpu_preprocessor.py` 硬依赖 `import cupy`，在无卡机器上直接崩溃——这是可运行性风险，而非亮点。

## 3. 核心模块设计

### 3.1 热像素识别

**判据**：跨全序列位置固定且数值方差极小的像素。

对 36 帧逐像素取时间轴统计量，标记满足 `median > 背景 + 5σ` 且 `std / median < 0.05` 的像素。目标与恒星因视场移动不可能满足该条件（它们只在少数帧经过某像素）。

输出 `hotpixel_mask.fits`，在探测阶段前应用。

### 3.2 单帧探测基线

阈值定为 **5σ, npixels ≥ 5**，直接依据 §1.3 的可复现性实测（90.3%）。阈值可在配置中调整，但默认值必须是可辩护的那个。

背景与 RMS 用 128×128 网格 + sigma-clip 中位数估计，双三次插值放大——延续现有实现的思路（该部分设计本身是合理的）。

PSF 用 2D 高斯 + 常数基线拟合，给出亚像素中心、FWHM、椭率、残差比。这是定位精度的主要来源，保留原规划中的这一正确判断。

### 3.3 配准求解

两阶段，兼顾稳健性与精度：

1. **粗解**：旋转角在 ±1.5° 内以 0.1° 步长扫描，每个角度下对位移做二维直方图投票（4 px 分箱），取票数最高者。已实测在 f00→f35 全程稳定收敛（§1.5）。
2. **精解**：以粗解为初值做星点匹配，对内点用最小二乘拟合完整仿射（或限定为相似变换），迭代剔除离群点。

变换模型采用绕视场中心的旋转加平移，允许可选的各向同性缩放以吸收残余畸变。

**质量门禁**：内点数低于阈值（默认 30）的帧对标记为配准失败，进入降级路径而非静默产出错误结果。

### 3.4 双坐标系交叉确认

对每个候选源计算两个运动量：
- `v_det`：在探测器坐标系中的逐帧位移
- `v_sky`：应用配准变换后在天球坐标系中的逐帧位移

判决规则（默认阈值如下，均可在 `config/default.yaml` 中调整）：

- `v_det` 小：中位帧间位移 < 5 px/帧
- `v_sky` 大：中位帧间位移 > 30 px/帧
- 像素锁定：整数像素位置在全序列不变，且峰值 `std/median < 0.05`
- 复现：在 ≥ 60% 的帧中被匹配到（匹配半径 3 px）

| 条件 | 判定 |
|---|---|
| `v_det` 小 且 `v_sky` 大 且 非像素锁定 | **空间目标** |
| `v_det` 大 且 `v_sky` 小 | 恒星 |
| `v_det` 小 且 `v_sky` 大 且 像素锁定 | 热像素 |
| 任一坐标系中不复现 | 噪声 |
| 两系皆小 或 两系皆大 | 未分类，进人工复核清单 |

阈值取值依据：实测目标 2–3 px/帧、星场 ~180 px/帧，f00–f04 段星场仅约 2 px/帧。因此 f00–f04 这一"机架近静止"区段无法用双系判据分离（两系皆小），判决只在 f05–f35 区段生效，前 5 帧的目标位置由 f05 起的轨迹反向外推后做局部确认。这一限制在报告中显式说明。

每个判定都记录支撑证据（两个速度值、复现帧数、像素锁定标志），供报告与答辩引用。

### 3.5 星场叠加

用配准变换将 36 帧重采样到公共天球坐标系后取加权平均。

理论增益：噪声按 √N 下降，N = 36 时约 6 倍，即约 **1.9 mag** 的深度提升。这把 30 ms 的浅曝光转成有意义的星表，使星点计数与星等定标建立在深场而非单帧之上。

叠加时以热像素掩膜与逐帧质量权重加权；目标本身在天球系中运动，会在叠加图中被平均掉（这正是期望行为——叠加图用于恒星，不用于目标）。

### 3.6 可复现性验证器

这是本项目的**论证基础设施**，不只是测试工具。

给定阈值扫描范围，自动产出"检出数 vs 阈值"与"复现率 vs 阈值"双曲线，即 §1.3 表格的完整版本。该图直接回答"为什么只报 200 颗星"这一必然被追问的问题，也是把"别人多报了"从主张变为论证的关键。

## 4. 比赛内容映射

### 4.1 星图识别（25 分）

两个方向均完成（科学性满分档要求"同时完成了两个方向题目"）。

**星点识别**：在指定单帧上以 5σ 基线给出星点总数（10² 量级），并附：
- 可复现性曲线，论证阈值选择
- 与 SExtractor 的交叉匹配诊断，定量说明差异来源
- 叠加深场的对照计数

**星等识别**：找出最暗星并标注星等。路径为盲板求解 → 星表匹配 → 零点反推 → 绝对星等（§5）。若联网或求解失败，降级为仪器星等并显式标注该限制。

### 4.2 星图分析 — 动目标识别（35 分）

主结果：QIANFAN-16 的完整轨迹（36 帧逐帧位置、亚像素精度、角速度）。

架构上不设"只找一个目标"的假设——双坐标系判决对任意数量目标同等适用。用户补全 15 张图的多目标数据后可直接复用。

创新性论证点：双坐标系交叉确认是本方案的原创构造，其出发点（识别出"望远镜在跟踪目标"这一观测配置）本身即为分析成果。

### 4.3 创新赛项（30 分）

满分档要求"4 个及以上创新有效分析数据"。规划如下（均由主流水线的中间产物自然导出，非硬凑）：

1. **系统自标定**：像元比例尺 ≈ 6″/px、视场 ≈ 6.8°，由机架转动率与实测场移互推得出，无需外部标定源。
2. **目标 J2000 轨迹**：赤经赤纬时间序列，**以赛方 `.DAT` 格式输出**（格式取自 `说明文件.txt`），便于与官方真值直接比对。
3. **轨道高度反演**：由角速度反推轨道高度，与 NORAD 60394 的公开 TLE 交叉校验——实用性分项的有力支撑。
4. **目标光变曲线**：逐帧测光给出光变，用于判断姿态稳定性/自旋周期。
5. **传感器健康度**：热像素图与噪声统计。
6. **观测条件**：视宁度 (FWHM 统计) 与天光背景亮度 (mag/arcsec²)。

第 3 项对"分析所得数据对现实场景有实际意义"（实用性 10 分）最为直接：轨道高度是太空交通管理的基础量。

## 5. 星等绝对定标（增强路径）

按用户决定采用盲板求解，但**分阶段实施以隔离风险**。

**第一阶段（无网络依赖）**：仪器星等 `m_inst = -2.5 log10(flux)`，全流程离线可跑。保证基础分不依赖外部服务。

**第二阶段（增强）**：
1. 在叠加深场上做盲板求解，得到 WCS。初值可由 `AZIMUTH`/`ELEVATIO` + 台站坐标 + 时间换算的指向（实测 f00 指向 RA 148.43°, Dec 33.04°）提供，把盲搜索收窄为局部匹配，大幅提高成功率。
2. 匹配 Gaia DR3 / Tycho-2 亮星，最小二乘拟合零点，得绝对星等。
3. 目标像素坐标经 WCS 转 J2000，产出 §4.3 第 2 项。

**降级策略**：求解或联网失败时，输出仪器星等并在报告中明确标注定标状态。基础分不会因增强项失败而丢失。

风险说明：`astroquery` 当前未安装，需加入依赖；星表查询依赖网络。这是我们把它定为增强项而非核心路径的原因。

## 7. 错误处理

系统面向答辩场景，**宁可显式失败并说明，不可静默产出错误数字**。

| 情形 | 处理 |
|---|---|
| FITS 头非标准（实测 `AZIMUTH` 卡片不合规） | `verify('silentfix')` 后读取，记录修复项 |
| 配准内点不足 | 标记该帧对失败，排除出叠加，报告中列明 |
| PSF 拟合不收敛 | 保留质心结果，置 `psf_fit_failed` 标志，不参与精度统计 |
| CuPy 不可用 | 静默回退 CPU，日志记录后端 |
| 星表查询失败 | 降级为仪器星等，报告标注定标状态 |
| 目标数为 0 | 明确报告"未检出"，不放宽阈值凑结果 |

## 8. 测试策略

| 层级 | 内容 |
|---|---|
| 单元 | 配准变换的正确性（合成已知旋转+平移，验证求解精度）；PSF 拟合（合成已知高斯，验证亚像素误差）；热像素判据；星等公式 |
| 后端一致性 | CPU 与 GPU 背景建模结果在容差内一致 |
| 集成 | 全流水线在真实 36 帧上跑通，产出全部分级产物 |
| 回归 | 关键数字（星点数、目标位置、角速度）纳入基线快照，防止改动引入静默偏移 |
| 物理自洽 | 像元比例尺的两条独立推导路径互相校验；轨道高度与公开 TLE 比对 |

合成数据测试尤为重要：真实数据无真值，只有在合成数据上验证过精度，才能定量声明亚像素定位能力。

## 9. 与原规划的差异说明

`规划.md` 中以下判断经实测确认正确并予保留：
- PSF 拟合是单帧精度的主要来源
- 阈值应基于局部 RMS 而非全局固定值
- 多帧信息比单帧更可信
- 物理约束优先于经验规则
- 所有模块应可量化评估

以下需要修正：

| 原设计 | 问题 | 修正 |
|---|---|---|
| `speed < 0.5 → STAR` | 本数据集下方向相反 | 双坐标系判决 |
| 候选生成"宁可多报不可漏报"，2.0–3.0σ | 实测 90% 虚警，与"数据准确"冲突 | 5σ 基线 + 可复现性论证 |
| 无热像素处理 | 会被误判为高置信目标 | 热像素图前置剔除 |
| 单帧独立处理 | 30 ms 曝光过浅，无法支撑星等工作 | 运动补偿叠加 |
| GPU 为主路径 | 评委机器可能无 CUDA | CPU 默认，GPU 可选 |
| 以 SExtractor 为标准基准 | 其默认参数在本数据上同样虚警主导 | 改为交叉匹配诊断工具，非真值 |

关于 SExtractor 的定位调整值得强调：它仍然有用，但用途从"基准真值"变为"差异诊断对象"。`规划.md` 附录中关于交叉匹配"验尸"的思路是对的，本设计将其制度化为 §3.6 的验证器。

## 10. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| 数据集只有 1 目标 36 帧，题面要求 15 图多目标 | 无法完全覆盖原始题面 | 用户补全数据；架构不假设目标数量，可直接复用 |
| 无 `.DAT` 真值 | 无法定量验证绝对精度 | 盲板求解 + 星表定标；物理自洽性交叉校验 |
| 盲板求解可能失败 | 星等定标受影响 | 分阶段实施，降级为仪器星等 |
| 星点数 ~10² 与直觉不符 | 可能被质疑"漏检" | 可复现性曲线 + 视场/曝光独立推导 + SExtractor 差异诊断 |
| 评委机器无 GPU | 程序无法运行 | CPU 默认路径 |

最后一项风险的处理方式，也是本设计把"星点数偏少"从弱点转为亮点的方式：主动、定量、多路径地论证这个数字为何正确，比报一个大数字更能体现科学性。
