- 轨迹报告新增区间覆盖、缺失帧数、最长连续漏帧；均为描述量，不是概率。

- 新增 `total_seconds`，包含出图和交互预览；工作台另记进程启动到导出完成的总耗时。
- 前端资源纳入源码包。没有增加生产 Python 或 JavaScript 依赖。

## 启动与使用

需要 Python（网页服务仅用标准库）、正在运行的 Docker、已有 `star-chart:cpu` 镜像。
科学计算依赖仍在镜像内。默认 `--pull=never` 禁止自动下载镜像，计算容器使用 `--network none`。

```powershell
.\scripts\demo.ps1
```

浏览器打开 `http://127.0.0.1:8765`。也可运行 `python -m src.webapp --port 8765`。
若已自行安装完整科学计算依赖，可用 `python -m src.webapp --runtime local`。
界面可在没有计算环境时查看已有结果，启动识别失败会显示日志。

数据放在项目 `data/` 下。官方数据选择 `rst19`，默认 f7 即第 8 张。
数据格式及定标范围见 `docs/reports/rst19-2026-09-23.md`。
随包 Gaia 星表适用于官方天区，其他天区需另配星表；页面可关闭定标。

CLI 保持兼容，新参数 `--viewer` 导出交互预览和目标切片：

```powershell
.\scripts\dr.ps1 python -m src.cli --input data/rst19 --reference-frame 7 --catalog docs/reference/rst19-gaia-dr3.csv --viewer --output output/new-demo
```

每次使用新的输出目录。前端自动分配唯一目录；运行日志先保存到独立目录，避免触发算法的非空输出保护。
完成后运行目录包含 `job.json` 与 `run.log`。旧报告缺少交互预览时仍可查看表格和成果图，重跑可生成预览。

## 验证实验

在页面“算法验证”中启动，或：

```powershell
.\scripts\dr.ps1 python -m src.validate.benchmark --output output/new-benchmark
```

默认 3 个种子 × 3 类场景，每组 512×512、12 帧、2 个物理运动目标。
图像含固定星场、渐变背景、高斯噪声、饱和点、随机瞬时源，以及特意构造的“移动但无曝光拖尾的闪点”负对照。
三种方法共享同一组检测和配准，只改变拖尾核验或漏帧容忍。

评估采用一对一轨迹分配：至少 4 个时刻且至少 80% 预测观测距可见注入位置不超过 3 px。
重复/碎片轨迹不能重复领取真值命中，额外轨迹计为 FP；无预测时 Precision 为 null。
定位 RMSE 和可见帧覆盖只统计成功匹配轨迹，需与漏检数一起解释。
源码校验值、种子、参数、逐场景结果随 `benchmark.json` 保存。

**这些实验不估计官方数据准确率，也不证明对复杂拥挤场有相同效果。**
生成模型与核验的物理假设一致，负对照是定向构造；还需要真实背景注入与人工核查。
