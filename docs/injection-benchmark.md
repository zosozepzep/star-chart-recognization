# 真实背景注入回收与峰值门限对照

这是 `docs/national-upgrade.md` 中真实背景评测的实现。输入是官方天基 FITS，
输出是已知注入目标的回收结果，以及与未注入背景配对的候选轨迹变化。
它不修改识别入口的参数，也不提供官方真实目标的准确率。

## 运行

需要 `data/rst19/` 与已有的 `star-chart:cpu` 镜像。默认协议：

```powershell
.\scripts\dr.ps1 python -m src.validate.injection --input data/rst19 --output output/new-injection
```

每次使用新的空输出目录。完全禁网运行可用：

```powershell
docker run --rm --pull=never --network none -v "${PWD}:/workspace" -w /workspace -e PYTHONPATH=/workspace -e MPLBACKEND=Agg star-chart:cpu python -m src.validate.injection --input data/rst19 --output output/new-injection-offline
```

协议文件为 `src/config/injection.yaml`；另存一份后可通过 `--protocol <文件>`
改变实验网格。协议必须包含生产峰值门限，调参与留出种子不得重复。
当前网页的“算法验证”仍运行此前的纯合成消融；本实验使用上面的独立命令。

## 固定协议

| 项目 | 默认设置 |
|---|---|
| 图像 | 官方序列全部 15 帧；每例使用 768×768 原始像素裁块 |
| 调参 | 种子 41、137、809；图像左半幅 |
| 留出 | 种子 1709、2027、4093；图像右半幅 |
| 注入亮度 | 每次曝光的总信号 600、1800、5400 ADU |
| 注入速度 | 探测器坐标系 2、6、12 px/s |
| PSF 与拖尾 | 圆高斯 σ=1.15 px，按实际曝光时间积分匀速直线拖尾 |
| 扫描参数 | `space.motion.min_peak_adu`：40、60、80 ADU |
| 其余检测参数 | 使用生产配置，包含 4σ 检出门限与原拖尾核验 |
| 规模 | 54 个注入图像序列、6 个未注入对照；每个序列扫描 3 个门限 |

调参与留出裁块在像素上不重叠。每个种子的裁块、轨迹中点与方向预先固定，
亮度/速度对照共享同一背景。注入位置只受几何边界约束，**不根据星点、背景亮度
或检出结果挑位置**，也不剔除发生融合的困难样本。同一集合内裁块可能重叠。

裁块排除了真实遥测行，因此仅在本实验的配置副本中设置 `metadata_rows=0`，
避免把裁块首行的科学像素误当成遥测。报告保存原始配置和实际使用的配置。
坐标均为 0-based `[x, y]`；原图坐标等于 `truth_xy` / 预测 `xy` 加裁块 `bounds`
中的前两项。逐帧轨迹中心对应原序列观测时间，速度及曝光长度均使用实际秒数。

亮度是离散 PSF/拖尾像素之和，不是峰值、仪器星等或 Gaia 星等。
同样总流量在更快的拖尾上会分散到更多像素。每帧记录标称流量、实际加入流量、
注入分量峰值与坏像素遮挡比例。负值、饱和及非有限像素保留原值；新注入后超过
饱和门限的像素由正常识别流程处理。已有背景噪声保留，未额外模拟源光子噪声。

## 评估与选参

每个图像序列独立执行背景估计、检测、配准、关联与拖尾核验。
同一序列的峰值门限扫描共享检测和配准结果；不同注入亮度/速度不共享这些结果。
推理接口只有图像、时间与曝光信息，注入真值只传给评估器。

一条预测至少在 4 个可见时刻、且至少 80% 的预测观测位于真值 3 px 内，
才有资格匹配。采用一对一分配，一条注入最多记一次回收。重复/碎片预测不重复
领取回收，定位 RMSE 与可见帧覆盖仅统计成功匹配的轨迹，必须和漏检数一起读。
所有几何可见注入都进入分母，包括因坏像素、融合或核验失败而漏掉的目标。

未注入对照也按每个门限运行。评估按以下方式归属预测：

1. 匹配注入轨迹：记为回收；如果未注入对照已能匹配这条真值，则记为歧义，
   不给回收信用，仍保留在分母中。
2. 剩余预测一对一匹配未注入对照：记为已有背景候选。
3. 再剩余的预测：记为“新增未归属轨迹”，供人工复核；可能包括碎片、误关联，
   也可能包括注入后发生变化的真实背景候选。

**没有完整真实目标标注，因此不把所有未匹配轨迹称为 FP，不计算真实 Precision。**
报告中的未归属数量是各次运行的计数之和，同一背景候选可能在不同实验中重复出现。

选参只使用调参集：优先回收数最多，再比较新增未归属数量，平手时优先靠近生产
门限，再优先较高门限。进入首个留出裁块前写出 `selection.json`，此后不改选参。
留出集按预先声明的同一网格报告结果，不用它重新选门限；程序不修改生产 YAML。

## 产物与复核

| 文件 | 用途 |
|---|---|
| `protocol.json` | 计算前落盘的协议、裁块、原始/实际配置、输入/源码 SHA-256、环境版本 |
| `controls.json` | 每个裁块与门限的未注入候选、坐标及耗时 |
| `selection.json` | 留出计算前冻结的选参依据与时间 |
| `cases.jsonl` | 每完成一个门限立即追加的逐例结果、真值、实际信号、预测及核验证据 |
| `injection.json` | 完整报告；成功完成时生成 |
| `recovery.csv` | 按集合、门限、注入流量、速度分箱的汇总 |
| `recovery.png` | 调参与留出回收曲线 |
| `report.md` | 可直接阅读的分箱表与限制说明 |
| `failure.json` | 中断于计算错误时保存原因及完成行数；不生成成功报告 |

共享流水线耗时包含一次原始基线关联；各门限另记关联与拖尾核验时间。
不要将单个门限的关联耗时当成完整识别耗时，也不要把三行共享时间相加。
总时间包含协议清单生成、全部重复计算与汇总图文导出，不代表 4096×4096 全幅
现场识别耗时。异常退出后换新输出目录重跑，原始 FITS 不会被写入。

留出虽使用不同像素与种子，仍来自相同天区、设备和时段。每格只有 3 条注入，
同一背景跨格复用，结果具有相关性。理想圆高斯 PSF、匀速运动和未加入源光子噪声
也限制结论范围。应先核查漏检与新增未归属轨迹，再决定是否调整生产算法。

## 逐阶段回溯诊断

完成实验后，可用独立工具重放并解释漏检：

```powershell
.\scripts\dr.ps1 python -m src.validate.injection_review --report output/injection-20261015/injection.json --input data/rst19 --output output/new-injection-review
```

默认复核原 `holdout`，可用 `--split tuning` 复核调参集。工具从原报告读取配置，
核对原源码与 FITS 校验值，并核对重跑的轨迹坐标和计数；不接受静默换参数的回放。
如已修改生产源码，应恢复相应实验版本到独立目录后复核，避免覆盖当前工作。

输出包含逐阶段计数、逐帧门限与信号、未归属轨迹的完整观测，以及原图/注入图/
注入分量/分割区域四列对照图。阶段分类表示首先未满足的必要条件，不等于唯一原因。
完整源表明细存于 `cases.jsonl`，体积较大；阅读时优先打开 `report.md`、`stages.csv`
和 `track-observations.csv`。本轮结果见 [`轨迹复核与漏检定位`](reports/injection-review-2026-10-15.md)。

回溯诊断不修改原 TP 计数，也不放宽匹配规则。诊断中用过的原留出数据不再是
后续优化的未见数据，应为新算法另准备验证数据。
