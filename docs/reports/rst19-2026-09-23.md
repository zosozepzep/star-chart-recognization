# 第 19 届官方天基数据：运行与针对性优化

输入为用户从赛事官网取得的 `data/rst19/`：15 张 FITS，以及《天基图像数据格式说明》。
本报告与此前 A/B 地基实测分开。默认演示选择 f7（第 8 张），文件为
`20260330163215892_9901.fits`；裁判指定图像后应调整 `--reference-frame`。

## 复现

```powershell
.\scripts\dr.ps1 python -m src.cli --input data/rst19 --reference-frame 7 --catalog docs/reference/rst19-gaia-dr3.csv --output output/rst19-run
```

Linux 用 `bash scripts/dr.sh` 替换 PowerShell 启动器。使用已有 `star-chart:cpu`
镜像，约 1.01 GB；新增功能没有添加依赖，也不需要重建镜像。首次环境准备仍需构建
Dockerfile；若裁判离线，应另提供该镜像和官方原图。源代码压缩包不包含约 480 MiB
的官方 FITS，也不包含镜像。

本机完整分析约 79 秒（不含最后保存两张图），独立数据表和全部参数存入
`report.json`，另有 `stars.csv`、`targets.csv`、`faintest-star.png`、`motion-tracks.png`。
报告记录全部输入 FITS 的 SHA-256、所用参考星表校验值、每颗定标星的配对与剔除结果。
原始像素文件不被修改。该版离线解压复验回执现存于
`dist/history/2026-09-23-pre-cleanup/rst19-receipt.json`；当前整理版的交付记录见
`dist/submission-receipt.json`。

## 发现的问题与修订

1. 原地基流程因负像素而停止。FITS 的 BITPIX=16、BZERO=0 表示有符号像素；
   新分支保留这个含义，屏蔽负值、≥30000 ADU 像素和周围 8 px，不做无依据的无符号转换。
2. 第一行前 208 字节包含 26 个 double 辅助量。按官方附录逐 16 bit 交换字节后解码，
   核对指向、位置和四元数；整行不参与光学识别，保留原有 x/y 原点。
3. 天基头的 AZIMUTH=270°、ELEVATIO=0° 是安装方向。新分支分析全部 15 帧，不用其
   常量判断地基机架状态。图像中的恒星背景基本静止，因此也不套用时间平坦度热像素剔除。
4. 每帧约 1.85 万个搜索源。配准只取至多 250 个紧致亮源，逐帧直接配到参考帧，
   加入一对一匹配、残差剪裁和 RMS 上限，控制密集星场的二次复杂度。
5. 运动判据改为相对恒星背景的运动，以实际 UTC 时间拟合，允许最多连续漏检 2 帧，
   最少 4 帧，速度范围 1–150 px/s，拟合 RMS≤1.5 px。候选不能复用同一源观测。
6. 用每帧曝光 1.5 s 和拟合速度预测拖尾方向与长度，至少一半观测需形态相容。
   初步 28 条轨迹中，有 2 条高速短轨迹缺少应有拖尾，被此检查剔除。
7. 增加离线 Gaia DR3 三角形匹配、二次切平面位置拟合和稳健测光零点估计。
   不从目标真值取得星等；参考星表来自 CDS，来源与适用范围见
   `docs/reference/rst19-gaia-dr3.md`。

格式说明写有 4096×4098，实际 FITS 头和有效像素区均为 4096×4096，程序以文件
真实布局为准。Astropy 的文件长度提示来自末尾缺少 448 字节块填充，完整像素区仍可读取。

26 条候选在 CSV/JSON 内逐一编号。轨迹图显示全部候选，并给出长轨迹和高速候选的
三时刻原图切片。单帧拖尾不会仅凭形状就计入已确认轨迹；少于 4 帧、特别弱的目标，
以及混叠造成长间断的轨迹仍可能漏检。此数值不等于真值目标总数或完备性成绩。

恒星计数也有明确边界：异常像素邻域、边界截断孔径、长条源被排除；没有做拥挤场
全面去混叠或注入回收实验。固定传感器缺陷仍可能通过重复性筛选。最暗者是这一明确
候选集合中的最暗源。相机滤光响应未知，Gaia 坐标自行未传播，不能把上述结果写成
标准 V 星等、无系统误差的 G 星等，或“已识别全部恒星”。

## 官网参考资料是否有用

核对入口：[赛事页面](https://spacemapper.cn/special/rst19/)、
[算法目录](https://spacemapper.cn/show/algorithm)、[数据目录](https://spacemapper.cn/show/data)。

| 官网资料 | 适合的用途 | 本轮处理 |
|---|---|---|
| 随包天基格式说明 | 正确解码姿态、位置、时间与非成像首行 | 已直接用于读取器与格式校验 |
| SGP/TLE、J2/J4、高精度轨道预报 | 有候选身份及对应历元轨道时做外部轨迹对照 | 暂不接入；不能由一条图像轨迹反推出唯一 TLE |
| 坐标转换、姿态确定 | 理解 J2000、WGS84、四元数和观测者位置 | 使用标准科学计算库离线实现所需转换 |
| 光学初定轨、精密定轨 | 取得可靠视线方向、观测者状态和足够观测弧段后的扩展 | 不把 21 秒短弧直接包装成可靠轨道 |
| 空间目标编目、轨道、光度数据 | 身份关联、历元匹配与外部验证 | 与本轮恒星测光使用的 Gaia 星表用途不同 |

公开算法目录主要是轨道与坐标服务，没有找到可以直接套用这批 FITS 的星点、最暗星
和多目标图像识别示例。它们有参考价值，但本项目核心检测与离线复现不依赖官网在线服务。
