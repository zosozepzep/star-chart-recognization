### 需要注意的两个实测细节

1. **数据集 B 跟踪段的 `daz_std` 是 0.0144，不是 <0.01。** 段内第一个增量
   `r16 (f16→f70 方向的 f16→f17)` 为 **+0.11899**，明显小于其余增量的
   ~0.2225——这是机架停稳前的余量。剔除这一个增量后，其余 53 个增量的标准差仅
   **0.0032**。f16 依真值
   时标确属跟踪段，故保留该帧、按实测修正标准差预期，而非挪动分段边界。

2. **数据集 A 确有一个可用的长跟踪段：f04–f35，共 32 帧。** 开头 f00–f03 的
   |ΔAZ| ≤ 0.0005°/帧（机架静止待命），被 `min_length=10` 自然排除，无需区分
   "静止"与"慢速跟踪"。A 的跟踪速率 +0.4749°/帧约为 B 的 2.1 倍，段内标准差
   0.0160 与 B 同量级，仍远低于 0.05 阈值。A 的跟踪段一直延续到序列末帧（f35），
   末尾没有回摆。

### `rms_max_px = 1.8567` 的归因：段首一对跨机架整定过渡

`rms_max_px` 的 1.8567 **完全由第一对 f16→f17 贡献**，其余 53 对落在
0.6229–0.8322。原因是几何而非质心质量：f16 跨在机架整定的尾部，
`azimuth_rates` 实测 f15→f16 = +0.549830、**f16→f17 = +0.118990**、
f17→f18 = +0.213910，之后稳定在 ~0.2214。段内 54 个增量的均值是 0.221442037，
所以 f16→f17 只有段内均值的 **53.7%**。这一对的场移也随之异常：
`shift_px[0] = 61.38 px`，其余 53 对全在 118.91–123.61 px。跟踪段 f16–f70 内
`exposure_ms` 恒为 30.0，所以这不是曝光时长造成的假象（f00–f07 是 80.0，但那几帧
在摆扫段内，不参与配准）。

这一对的残差是整体抬升而不是几个离群点：p50 = 1.6615，剔掉最差 5%（74→70 点）
重新拟合也只降到 1.6580。真正的判据是自由度对比——**同一组 74 对匹配点，4 参数
相似变换 rms 1.8567，6 参数仿射 rms 0.6618，比值 0.357**；而在健康对上 6 参数
没有收益（f17→f18 比值 0.9992、f32→f33 0.9865）。残差还呈强线性空间结构：
`corr(x, res_y) = -0.9090`、`corr(y, res_x) = -0.9449`，而同轴项只有
`corr(x, res_x) = -0.1186`、`corr(y, res_y) = +0.1039`，两轴残差均值都是 0——
交叉项强、同轴项弱、均值为零，这是切变的指纹。也就是说帧间映射在这一对上带
真实切变，4 参数模型按定义吸收不了它。

这组 1.8567 / 0.6618 对比，正是 `src/register/transform.py` 模块 docstring 里
"4 参数吸收不了切变"那段论证的真实数据佐证；它比 Task 9 用镜像点集造出的
`rms = 20√5 ≈ 44.7214` 更有说服力，因为它出自生产数据而非合成反射。

**这不是配准缺陷，也不是分段缺陷——没有任何东西需要改。** f16 依 `.DAT` 真值时标
确属跟踪段（本文件「机架状态分段」一节已用真值第 1 行 17:26:44.2670 对齐 f16 的
`DATE-OBS` 佐证过边界 `(16, 70)`），`tracking_segment` 把它收进来是**正确的**。
抬升的成因是纯物理的：真值说这一帧已经在跟踪，而机架此刻**尚未停稳**——同一节
记过的"段内第一个增量 r16 = +0.11899 明显小于其余 ~0.2225，这是机架停稳前的余量；
剔除这一个增量后其余 53 个增量的标准差仅 0.0032（含它是 0.0144）"，说的正是同一
件事。曝光窗口内机架还在收敛，帧间映射因此带上了 4 参数相似变换按定义吸收不了的
切变。

这个结论比"挪一下分段边界就能消除"要**强**：1.8567 是这条链路上不可回避的真实
值。真值把 f16 钉在跟踪段内，任何分段逻辑都甩不掉它——除非违背真值去裁帧，而那
是拿掉一帧真实数据来美化一个数字，方向正好反了。所以段首这一对的残差抬升被如实
记录并由分层断言看守，而不是靠放宽 `rms_max_px` 的上界掩掉。

守护测试 `test_dataset_b_registration_matches_measured_baseline` 因此不用单一的
`rms_max_px < 1.5`，而是分层断言：段首对 `< 2.0`、其余 53 对全部 `< 1.0`、
汇总 median `< 1.0`、且 `rms_max_px` 必须恰等于段首对的 rms（钉住"最大值来自
段首"这一归因本身）。段首对**不设下界**——将来质心精度改进使它降到 0.9 时测试
不该因此变红，强度由 `max(rest) < 1.0` 与 median 承担。

### `peak_flat_ratio = 1.3900` 为什么不参与判决

真目标的峰值平坦度是 **1.3900**，是设计文档 §3.4 引用的 0.05 的 **27.8 倍**。
所以峰值平坦度既不能当像素锁定的否决项，也不能当目标的正向判据——
真目标的峰值本来就在剧烈变化（它在动，足迹和邻域都在变）。
`pixel_locked` 只用探测器系跨度范数这一条绝对空间判据，
`peak_flat_ratio` 仅作报告旁证。裁定见 Ruling 48a / 338。


## 阈值-复现率曲线

这一节是 25 分星图识别题「科学性」论证的主证据，也是「为什么只报 10² 颗星」的
正面回答。它的特点是**不需要真值**——可复现性对着数据自身量（同一颗星是否在
多帧的同一天球位置重现），所以在无 `.DAT` 的数据集 A 上依然成立。
`src/validate/repeatability.py` 因此被硬约束禁止 import `src.validate.truth`：
一旦引入真值，报出的星数就变成答案文件的函数。

复现命令（容器内）：

```bash
SC_IMAGE=star-chart:cpu-interim bash scripts/dr.sh python probe/t14-final.py
```

### 两个必须分开的量

| 量 | 公式 | 回答的问题 | 值域 |
|---|---|---|---|
| **复现率** reproducibility | `n_reproducible / n_reference`，`n_reference = len(frames[0])` | 「你怎么知道这些是真星」 | 恒在 [0, 1] |
| **纯度** purity | `n_reproducible / n_detected_mean`（**非空帧**均值） | 「别人多报了」 | 可超 1 |

两者只在「参考帧探测数恰等于各帧均值」时相等。历史实现只报后者却称之为复现率
（裁决 66）：一帧全空时含空帧的均值被压低，纯度报成 **1.2000**——一个彻底失败的
帧把质量指标抬高 20%；帧间探测数不等时（参考帧 100 源、其余五帧各 200 源、
全部复现）它报 **0.545**，读起来像 45% 没复现，而真复现率是 1.000。
现实现把空帧从纯度分母排除，并把两个量分列。

### 噪声悬崖：这就是「263822 颗星」的反证

2σ → 5σ 之间探测数掉 **59 倍**（A：5880.50 → 99.67）与 **25 倍**
（B：2325.83 → 91.83），而复现率从 0.036 / 0.070 升到 0.800 / 0.630。
2σ 上每帧那 2000–5900 个「源」里只有 161–206 个能跨帧复现——
**其余 93–96% 是噪声峰**。这条曲线因此不是「调参记录」，而是
「为什么报 10² 而不是 10⁵」的定量依据。

### 偶然重合的下界：3 px 半径跨 4 帧不可能是巧合

`chance_match_probability` 在均匀密度 Poisson 近似下算「偶然满足复现判据的源数
期望」。4096² 场、3 px 半径、6 帧、`min_hits=4`：

| 探测数/帧 | 半径内期望邻居 | 单帧偶然匹配概率 | E[偶然可复现源] |
|---|---|---|---|
| 124（规格的报数档） | 0.00020897 | 0.00020895 | **1.13e-8** |
| 200 | 0.00033706 | 0.00033700 | — |
| 2284（2σ 量级） | 0.00384918 | 0.00384178 | **1.29e-3** |

判据松一档，数字涨好几个量级——2284 源/帧时 `min_hits` 取 4 / 5 / 6 分别给出
**1.287624e-03 / 2.480055e-06 / 1.911442e-09**。所以引用时必须带上判据：
`1.9e-9` 是 `min_hits=6`（**每一个**邻居帧都偶然匹配）那一档，
本模块用的「≥4 of 6」判据下诚实的数字是 **1.29e-3**（裁决 284）。

余量：2σ 上真实可复现源约 201 个（0.088 × 2284），比 1.29e-3 高
**5.2 个量级**（`min_hits` 取 5 / 6 时是 7.9 / 11.0 阶）。**不是九个量级**——
九阶在任何判据下都不成立（裁决 285）。5.2 阶已足以说明均匀密度近似不承重，
所以「3 像素半径是不是太宽松」有一个算得出的答案而不是一句保证。
注意这是**量级下界**而非精确速率：真实源成团，而估计假设均匀。

**`2284` 源/帧、纯度 `0.088`、真实可复现源约 `201` 这三个数是裁决 285 供给的
示意量级，不是本项目的实测值**（与任务书草稿在 4σ / 5σ 两档上给的示意星数同一
类别——那两个数依裁决 286 / 367 不得引用，见下文「报数阈值上的星数」一节）。
本项目 2σ 实测：
数据集 A 各帧均值 **5880.50** 源/帧、纯度 **0.0350**；数据集 B **2325.83**、
纯度 **0.0692**——**0.088 与两个数据集都不符**。它们在这里的作用只是论证余量的
**数量级**，所以「5.2 个量级」这个结论照裁决 285 保留不动，但引用时必须说明它
建立在这组示意量级上，而**不得**把 2284 / 0.088 / 201 当作 A 或 B 的实测量引用。

**并且要注意 5.2 阶不是余量的下界，示意量级在这里偏乐观**：探测数越大，
偶然重合涨得比真实源数快（`n × tail`，而 `tail` 随 `p_one³` 涨），所以余量随探测
数**缩小**。用本节两张表自己的 2σ 行算：A 是 206 / 5.55e-02 = **3.57 个量级**，
B 是 161 / 1.38e-03 = **5.07 个量级**——A 比示意值低 1.6 阶。结论的方向不变
（3.57 阶仍足以让均匀密度近似不承重），但**引用余量时要用本数据集自己那一行**，
不要引 5.2 去描述 A。

面积敏感性：同样 2284 个探测放进 2048² 场，期望邻居数从 0.00385 涨到
**0.01540**（恰 4 倍）；4096×4136 只挪到 0.00381。**面积的量级要紧，
具体帧尺寸不要紧**，所以 `image_shape` 必须取自数据而不能写死 4096²。

### 复现率达不到 1.0 的结构性原因：场滚出画幅

低仰角跟踪下场在滚动——实测 6 帧累计场移 A 845.13 px、B 600.04 px，5 步平均即
A **169 px/帧**、B **120 px/帧**（845.13/5 = 169.03、600.04/5 = 120.01）。
一个参考源要满足「≥4 of 6 帧」至少要活过 3 步，即 A **507 px**、B **360 px**，
占 4096 图幅宽的 **12.4% / 8.8%**（507/4096 = 12.3779%、360/4096 = 8.7891%）。
**滚出画幅的源无论探测多好都不可能复现**，所以复现率有一个
与阈值无关的上限。实测（用逆变换把参考源映回各帧探测器系、统计仍落在
0 ≤ x < 4096、0 ≤ y < 4096 内的帧数）：

| 数据集 | 6 帧累计场移 | 结构性上限 | 5σ 实测复现率 | 实测 / 上限 |
|---|---|---|---|---|
| A（f05–f10） | 845.13 px | **0.8842** | 0.8000 | **0.9048** |
| B（f17–f22） | 600.04 px | **0.8261** | 0.6304 | 0.7632 |

**这个比值才是方法质量的量**：在结构上有可能复现的源里，A 上找回了 90.5%。
剩下的缺口是探测阈值附近的抖动——实测未复现源的 flux 中位数只有已复现源的
1/2.6 到 1/3.8（B 5σ：247.0 对 934.1），即漏的都是贴着阈值的弱源，
这与「计数是下界」的方向一致。

**上表只给 5σ 一行是有意的：结构上限是每一档各自的量，不是一个常数。**
它取决于该档参考帧的源数与各源的滚出情况，而各档参考帧源数差别很大
（A：2σ 5791、4σ 126、5σ 95、8σ 62）。**拿一档的上限去除另一档的复现率，
得到的比值不代表任何东西**（裁决 370）。要给多档结论，必须对每一档各跑一次
逆变换统计、算出各自的上限——本项目未做，所以本文件只报 5σ 这一档的比值。

另测：把匹配半径从 3 px 放宽到 8 px，数据集 B 的复现率只从 **0.5816**
（**f16–f21** 窗口，含未停稳的段首帧）动到 0.6327——**3 px 不是约束的紧边**。
0.5816 这个数属于 f16–f21 窗口，**不是**本节交付的 f17–f22 窗口
（后者 5σ 是 0.6304，见上表）；结论不受窗口影响，但引用时必须带上窗口
（裁决「Minor 8」）。

**本节两张曲线表里没有「参考帧为空」的档位**：两个数据集的参考帧
（A f05、B f17）在全部九档上探测数都非零（最低 A 8σ 的 62、B 8σ 的 58）。
`cross_frame_repeatability` 对空参考帧按约定返回 `(0, 0.0, 0.0)`，
而这个 `0` 与「有源但一个都没复现」在数值上不可分——现有表中不存在这种档位，
所以表里的每一个 0.xxxx 都是真实的比值。（区分这两种情形要给
`RepeatabilityPoint` 加字段或跳档，是接口变更，记入最终评审待办。）

`test_scroll_off_caps_reproducibility_below_one` 守护这条归因：它断言实测复现率
**不得超过**结构性上限（超过就说明有源滚出画幅后仍被判命中，即匹配或配准有误）。

### 与规格 90.3% 的关系：**两个数都对不上，且规格未说清它是哪个量**

规格 `docs/superpowers/specs/2026-09-08-太空目标识别系统.md:78` 给出

|---|---|---|---|
| 探测数 | 124 | **99.67**（参考帧 95） | −20% |

### `recommended()` 与 `detect.report_n_sigma` 的关系当前无法求值

`recommended(min_reproducibility)` 取「自身及所有更高阈值都达标」的最低 σ
（单调合格后缀），而不是合格集里最小的 σ——后者会选中一个上邻居不达标的点：
曲线 `[(2.0, 0.10), (3.0, 0.88), (4.0, 0.60), (5.0, 0.91)]` 在门限 0.85 下
原判据选 3.0，而 4.0 只有 0.60（裁决 69）。

默认门限 **0.85 在两个数据集上都无一档达到**（A 最高 0.8289 @6σ，
B 最高 0.6892 @3.0σ），所以 `recommended()` 按设计抛错，
裁决 68 要求的关系 `recommended() ≤ detect.report_n_sigma` 当前**求不出值**。
在曲线能求值的门限上，该关系成立：

| 门限 | A 的推荐值 | B 的推荐值 |
|---|---|---|
| 0.85 / 0.80 | 抛错 | 抛错 |
| 0.75 | **4.0σ**（≤ 5.0 ✓） | 抛错 |
| 0.70 | 3.5σ（≤ 5.0 ✓） | 抛错 |
| 0.60 | 3.0σ（≤ 5.0 ✓） | 3.0σ（≤ 5.0 ✓） |

配置的 `report_n_sigma: 5.0` 因此比方法在任何可求值门限下的推荐都**更保守**
（少报星），方向是可辩护的那一侧。0.85 这个门限与实测曲线的差距、
以及数据集 B 5σ 复现率 0.6304 与任务书 0.85 的差距，
均在 `tests/validate/test_repeatability.py` 里有测试守着——
**门限数字一字未动**，一旦实测越过它，测试会转红强制重新裁决。两处手法不同：

- 数据集 B 的 0.6304 vs 0.85 那条仍是 `xfail(strict=True)`：断言体只有一个可失败点
  （`by_sigma[5.0].reproducibility > 0.85`），strict 隔离得住。
- 数据集 A 的默认门限那条**已改为正向断言**
  （`test_default_threshold_is_unreachable_on_the_measured_curve`，
  用 `pytest.raises` 断言 `recommended()` 今天求不出值，今天就是绿的）。
  原来它与裁决 68 的关系断言共处一个函数体，而 `xfail(strict=True)` 只能隔离
  「整条测试」不能隔离「其中一步」——一旦复现率越过 0.85，`recommended()` 会返回
  6.0σ、`assert 6.0 <= 5.0` 失败，却**仍被记为预期失败**，把裁决 68 要守的违规
  静默掉（裁决 368）。拆开后裁决 68 的关系由
  `test_recommended_relationship_holds_at_the_measured_threshold` 独家守卫。

## 目标轨迹时序表与角速度

复现命令（容器内）：

```
SC_IMAGE=star-chart:cpu-interim bash scripts/dr.sh python -m pytest tests/target/test_trajectory.py -v
```

链路：`tracking_segment` → `build_from_sequence`(前 30 帧) →
`detect_sequence(n_sigma=4.0, hot_clusters=...)` → `register_sequence(reference=seg.start)`
→ `find_targets(...)[0].track` → `build_trajectory(trk, seq, 6.179)`。
得到轨迹 **f17–f70 共 54 帧**，相邻对 **53** 对。

### 三条必须先说清的口径（PPT 与答辩照此说）

1. **派生数据集 1 报角速度与弧长，不报赤经赤纬。** 轨迹图的位置轴是**天球系
   像素坐标**（`xy_sky`，配准后），不是赤经赤纬。`TrajectoryPoint.ra_deg` /
   `dec_deg` 恒为 `None`。
2. **所有 arcsec 量都是真值定标量。** 6.179 ″/px 由 `.DAT` 真值定出
   （`TruthReport.plate_scale_arcsec_px`，逐步比值的均值实测 **6.179047**）；
   FITS 头 **28 张卡片逐个看过，没有焦距、没有像元尺寸、没有 WCS**。
   可以说「像素系 **125.7334 px/帧**（53 步均值）由识别链独立测得，换算所用
   比例尺来自真值定标」；**不得**声称角速度独立验证了真值。与 Task 17 的零点同类。
3. **不得报位置角。** 被问「轨迹朝哪个方向」答：「天球系像素方向
   **95.6670° ± 0.7767°**（`atan2(off_x, off_y)`，53 步统计）；转成天文位置角
   需要视场定向标定，在本轮范围之外。」实测真值位置角（自北经东）均值
   **321.9317°**（std 1.4255），与像素系方向相差 **226.2648°**——那 226° 整个落在
   未解的翻转+旋转里。

### 角速度（口径：`xy_sky` × 6.179 ″/px，54 帧 53 对）

| 量 | 实测 | 口径 |
|---|---|---|
| `mean_rate_arcsec_s` | **770.150748** | 53 个相邻对速率的均值 |
| `rate_std_arcsec_s` | **5.908426** | 同 53 个值，`ddof=0` |
| `std/mean` | **0.007672** | — |
| min / max | 756.1243 / 780.2388 | 53 个值 |

### 切平面误差预算：为什么用严格 TAN 而不是线性近似

切点取真值第 0 行 (209.23627, 12.35454)，目标端点经严格 TAN 正投影得到切平面
偏移 (−25614.6558, +33930.7378)″：

| 方法 | 往返误差 | 换算像素 |
|---|---|---|
| 线性近似 `ra0 + Δx/cos(dec0)` | **1189.4823″** | **192.50 px** |
| 严格 TAN（gnomonic） | **1.15e−11″** | 1.9e−12 px |

视场本身 4096 px × 6.179 ″/px = **7.0303 度 = 421.82 角分**——注意不是
「7 角分」，那个说法错 60 倍。`offset_to_radec` 因此实现为严格 TAN。
零偏移的往返 `offset_to_radec(209, 12, 0, 0)` = `(209.0, 12.000000000000002)`
——赤纬差 **2 ulp**（`arctan`/`hypot` 的舍入），**不是逐位精确**，测试用
`abs=1e-12`（余量约 500×）且函数名叫 `..._round_trips` 而不是 `..._is_exact`。

该函数在本轮**不被 `build_trajectory` 调用**（没有盲板求解提供切点），是纯函数
加测试，供国赛消费。届时两条实测陷阱：(a) 盲板求解返回的是**机架指向 = 画面
中心** (2047.5, 2047.5)，而目标 f17 在 (2271.6, 1958.8)，相差 241.0 px =
1489.2″ = **0.4137°**；(b) 以真值首行锚定依赖 `track.frames[0]` 恰为真值第 0 行
那一帧，真值一步中位数 **778.777″ = 0.2163°**，少一帧就整体偏这么多。

### 时基：角速度用相对秒，时刻记录用绝对秒

`angular_rates` 的 `times` 必须是 `(t - t[0]).sec` 相对秒。绝对 Unix 秒量级
1.7e9，float64 在那里的分辨率约 **2.4e−07 s**：

| 时基 | 1.008 s 节拍的实际步长 | mean 相对误差 | 速率 std |
|---|---|---|---|
| `t.unix` | 1.0079999 .. 1.0080001 | **2.59e−09** | **9.008e−05** |
| `(t - t[0]).sec` | 1.008000000 ±1e−11 | **4.02e−14** | **3.412e−09** |

而 `TrajectoryPoint.time_unix` 是**记录用的绝对时刻**，`duration_s` 由它相减
（19 s 跨度误差 1.2e−08）。**不得**绕 `isot` 字符串往返：`isot` 默认 3 位小数，
节拍 1.008 / 1.009 / 0.030 s 时损失恰为 0，但 **1.0075 s 时损失 5.0e−04 s**。

**这条只能由 20 点合成夹具钉住**：在真实 dataset B 数据上两种时基给出的均值
**逐位相同**（都 770.150748），所以数据集断言抓不到换时基这个错误。同类抓不到的
还有：节拍硬编码 1.008（偏 0.72 ″/s）、`times()[frames]` 错 1 帧（偏
0.126–0.169 ″/s）。

### 1. 可行高度区间表

轨道面相对测站铅垂面的取向未知，横向速度分量只能界定在
`v·cos(θ_sat) ≤ |v_⊥LOS| ≤ v` 之间（`sin θ_sat = R cos E /(R+h)`）；测站自转
`ω_E·R·cos(纬度)/ρ` 的符号随过境方位而变（实测 `AZIMUTH` 从 233.04° 扫到
283.97°，且 f08/f79 回跳），故并入区间而不带符号相减。

**测站项贡献的带宽是 +89.2145 km**（634.9181 − 545.7037）。
中点处环绕速度 **7.5956 km/s**。

**表内每个数都注明了是宽带还是裸带口径。混口径答辩时是一分。**

界与高度的对应关系容易弄反：两个界都随高度**单调递减**，高度 `h` 可行 ⟺
`lo(h) ≤ ω ≤ hi(h)`，所以 `lo(h)=ω` 的根是 `height_min`、`hi(h)=ω` 的根是

`n_increase = 0`：裸上界 2540.7378 → 13.6698、裸下界 913.9129 → 13.5496、
**宽带上界 2651.1964 → 15.2478、宽带下界 803.4542 → 11.9716**。后两个才是
`estimate_height` 真正反演的函数，故 `brentq` 的唯一性前提成立，未加二分回退。

### 3. 天光面亮度：条件命题

> **给定**真值零点 `15.335125 ± 0.217907`（数据集 B，`source="truth"`，
> `exposure_s is None`，即零点已是流量率约定、面亮度不再除曝光）**与**真值板比例
> 6.179 ″/px，第 30 帧（曝光 30 ms）全帧中位 **6.0 / 5.0 ADU** 给出
> **17.34 / 17.54 mag/arcsec²**（B / A），落在城市微光夜空（~17）边缘。

**这是条件命题，不是独立观测量。** 这个数的全部信息量都在零点里：实测平移零点
1 mag，mu 平移 1 mag（逐位 1.000000）。

**不写小数位以下。** 背景中位是**整数** ADU（实测恰好 6.0 / 5.0），1 ADU 在 6.0 上
就折 0.18 mag；零点本身另有 0.217907 mag 的散度。两项都比小数位大一个量级。

### 4. 零点的两种约定 —— 「为什么面亮度不是 13 等」

同一批数据（`truth_mag=8.0`、`flux=5000` ×12、`t=0.030 s`）两次调用
`zero_point_from_truth`：

```
exposure_s=0.030 -> ZP = 21.054621874040890   (exposure_s 字段 = 0.03)
exposure_s=None  -> ZP = 17.247425010840050   (exposure_s 字段 = None)
差 = 3.807196863200840 = -2.5*log10(0.030)
```

两条**自洽**路径给出同一个 mu：19.178116700324768 / 19.178116700324772，
delta **−3.553e−15**（从函数派生才有这个精度；手写 `21.0546` / `17.2474` 两个
四位字面量之差是 3.8072000，mu 之差 3.14e−06）。

**错配**（用 `exposure_s=None` 的零点却仍除一次 t）给 15.370920，
偏 −3.807197 —— 就是重复扣除了一次曝光。**交付实现对这一路是抛
`ValueError`，不是算出这个数**：那个不一致是可检测的，静默挑一边会留下
3.807197 mag 的整体平移而没有任何痕迹。

早期的「13.4585，比任何真实夜空亮 3.5–8.5 星等」是**零点错配**的产物
（确有一次重复扣除），**不是公式方向错**。用自洽配对给出的 17.34 / 17.54
物理上说得通。

### 5. 各项的实测敏感度

| 扰动 | mu 的变化（实测） |
|---|---|
| 曝光 30 → 80 ms（同一流量率零点，只换 `exposure_s`） | **+1.064922**（= 2.5·log10(80/30)） |
| 背景 6.45 → 64.5 ADU（10 倍） | **−2.500000**（恰好） |
| 背景 6.45 → 20.0 ADU | 19.178117 → 17.949441 |
| 板比例 1.0 → 6.179 ″/px（面积项） | **+3.954591**（= 2.5·log10(6.179²)，像素面积 38.1800 arcsec²） |
| 零点 +1 mag | +1.000000 |

面积项是**加**的且方向已实测确认：per-arcsec² 的流量比 per-px 小 38.18 倍，
所以面亮度更**暗**。丢掉这一项会给 15.223526（低 3.954591）。

**曝光单调性的正确读法。** 上表第一行必须让两个零点**共用同一个 `value`、
只换 `exposure_s` 字段**。若改成对同一批 flux/truth_mag 各自重拟零点
（`_derive_zp(0.030)` vs `_derive_zp(0.080)`），则 `ZP(t) = ZP(None) − 2.5log10(t)`
把曝光项吸进零点、`b/t` 又贡献 `+2.5log10(t)`，两者**精确抵消**，
实测 delta = **0.0（逐位为零）**。那个抵消是「曝光由零点携带」这一条的同一事实，
不是单调性。「同一台设备两个曝光」的正确模型是一个流量率零点配两个 `exposure_s`。

物理带 `15 < mu < 23` 只是**合理性下限，不是变异杀手**：实测它的判别力随背景
变化，在 `b = 1 ADU` 处**归零**（此时 `inst_mag = 0`，符号翻转与正确实现给出
同一个 19.2896），`b = 100` 时连正确实现都被带拒（14.2896 落在带外）。
真正抓错的是三条载荷断言：曝光单调性、背景符号（10 倍恰好 2.5 mag）、面积项。

### 6. 跨历元一致性（**不依赖真值的自查**）

`fwhm_px` 与 `elongation_median` 都是纯像素量，所以这一条可以当独立主张：

```
跨 134.158023 天，不同曝光档（B 帧含 30/80 ms，A 帧含 30/40 ms；两侧取的第 30 帧
都是 30 ms）、不同目标（QIANFAN-7 / QIANFAN-16）、各自独立的背景建模与探测：
  fwhm_px            3.403649  vs  3.409136   差 0.005487 px（相对 0.16%）
  elongation_median  1.195896  vs  1.202717   差 0.006821
```

同一台光学系统在两次相隔四个半月的观测里给出逐千分之一一致的星像宽度，
这是对整条「背景建模 → 5σ 分割 → PSF 拟合」链路的一次端到端自查。
