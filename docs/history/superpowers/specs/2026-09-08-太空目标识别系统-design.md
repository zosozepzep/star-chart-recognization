## 0. 摘要

本项目重构为**双坐标系运动补偿架构 (Dual-Frame Motion-Compensated Architecture)**。

核心物理洞察：**望远镜在跟踪卫星，而不是跟踪恒星。** 因此在探测器坐标系中，目标静止、恒星拖动；在天球坐标系中，恒星静止、目标运动。系统在两个坐标系中同时探测，用两条互相独立的证据链交叉确认同一目标。

这一洞察同时修正了原有流水线中一个方向性错误，并解释了此前星点计数偏高约两个数量级的原因。

## 1. 数据事实核查 (Data Forensics)

本节所有数字均由脚本实测得出，是后续全部设计决策的依据，也是答辩时应对"原理性质疑"的第一道防线。

`说明文件.txt` 记载数据包应含 `.DAT` 定位文件（UTC 时间 + J2000 赤经赤纬 + 星等，即星等真值），但**该文件不在数据集 A 的压缩包内**。数据集 B 补上了这一环（§1B），因此星等绝对定标的主路径改为基于真值的离线定标（§3.7、§5），盲板求解 + 星表匹配降为交叉校验手段。对数据集 A 本身，仍只能给出仪器星等或经盲板求解后的绝对星等。

### 1.2 关键发现一：望远镜在跟踪卫星

FITS 头中 `AZIMUTH` / `ELEVATIO` 逐帧连续变化：

| 帧 | AZIMUTH | ELEVATIO |
|---|---|---|
| f00 | 88.74145° | 51.03962° |
| f05 | 89.20219° | 51.03437° |
| f20 | 96.51816° | 50.48447° |
| f35 | 103.46363° | 49.45124° |

方位角在 59 s 内扫过 14.7°，且 f00–f04 近乎静止、f05 起开始持续转动。这是**跟踪机动**，不是恒星跟踪。

三条独立证据确认：

1. **全场恒星整体位移**：f05 之后星场以约 180 px/帧 的速度整体扫过视场（网格投票法测得，见 §1.5）。
2. **存在帧内静止的亮源**：`(2231, 2104)` 处有一 flux ≈ 13000、elongation ≈ 1.1 的紧致源，在 f06→f14 期间逐帧位移仅 2–3 px，而同期整个星场移动约 180 px/帧。**这就是被跟踪的目标 QIANFAN-16。**
3. **PSF 形态**：目标近似圆形（elongation 1.02–1.20）而非拖长，符合"被跟踪物体成点像"的预期。

**对原有实现的影响**：`combat_mission.py:153` 的判据

```python
target_type = "STAR" if speed < 0.5 else "DEBRIS"
```

在本数据集上**方向完全相反**——帧内静止者才是空间目标，高速运动者是恒星。这是必须修正的原理性错误。

### 1.3 关键发现二：现有星点计数约 90% 是噪声

曝光仅 30–40 ms，星场本就稀疏。实测底噪：背景中位数 5 ADU，σ ≈ 3.45，无饱和像素（最大值 26975 < 65535）。

以"真实恒星必然在下一帧复现、噪声不会"为判据做交叉验证（已补偿帧间位移，匹配半径 2 px）：

| 阈值 | 检出数 | 次帧复现率 |
|---|---|---|
| 2.0σ, npix=5 | 5922 | **9.8%** |
| 2.5σ, npix=3 | 5999 | 11.8% |
| 3.0σ, npix=3 | 806 | 35.2% |
| 5.0σ, npix=5 | **124** | **90.3%** |

结论：低于 3σ 的"检出"绝大多数是噪声涨落。

因此仓库现存产物不可用于提交：
- `master_catalog.json` 声称 `confirmed_stars: 263822`、`eliminated_noise: "100%"`
- SExtractor 基准每帧约 9021 条

两者均以 2σ 量级阈值运行，虚警占主导。按评审标准，"星点星等数据准确"是科学性 15 分的核心，且专家每提一次未被说明的原理性质疑即扣分——提交 263822 这一数字风险极高。**单帧真实星点量级为 10² 颗（f00 在 5σ/npix5 下实测 124 颗，视帧与阈值在 100–250 之间）**，并附可复现性曲线作为论证（用户已确认采用此口径）。最终提交数字以指定帧的实际测量为准，本文档不预设具体值。

### 1.4 关键发现三：热像素

`(244, 3174)`、`(312, 3206)`、`(327, 3210)` 三处在全部 36 帧中数值几乎恒定（如第一处：f00 = 305, f35 = 309），位移恒为 0.0 px。

这是**传感器热像素/坏点**，不是天体。它们对本项目有双重意义：
- 现有跟踪器会把"完美静止"当作高置信度轨迹，将其误判为目标——必须屏蔽。
- 修正后的架构以"帧内静止"作为目标判据，热像素恰好是该判据的主要混淆源，**必须在时序判决前剔除**。

副产品：热像素图本身是创新赛项的一项有效分析数据（传感器健康度评估）。

### 1.5 关键发现四：配准需要旋转

帧间变换用"旋转 + 平移"网格投票测定（已屏蔽热像素，取最亮 150 源）：

| 帧对 | 最优旋转 | 平移 (px) | 内点数 |
|---|---|---|---|
| f00→f01 | +0.0° | (+2, −2) | 134/150 |
| f06→f07 | +0.4° | (−182, −14) | 64/143 |
| f12→f13 | +0.4° | (−178, −22) | 108/142 |
| f20→f21 | +0.4° | (−178, −34) | 101/146 |
| f30→f31 | +0.3° | (−170, −46) | 61/129 |

存在约 0.3–0.4°/帧 的场旋转，与地平式 (alt-az) 机架的视场旋转特性一致。**纯平移配准会导致叠加涂抹**，配准模型必须包含旋转。

（注：全帧相位相关法在此数据上失效——它锁定到逐帧完全相同的热像素上，给出恒为 (0,0) 的伪峰。这也从反面印证了热像素屏蔽的必要性。）

### 1.6 派生量：像元比例尺

由机架转动率与实测场移量互推：

- 天球角速度 ≈ Δaz × cos(el) = 0.48°/帧 × cos 51° ≈ 0.30°/帧
- 实测场移 ≈ 180 px/帧
- **像元比例尺 ≈ 0.30° × 3600 / 180 ≈ 6 arcsec/px**
- **视场 ≈ 4096 × 6″ ≈ 6.8°**

这是一个宽视场系统。两点推论：
1. 6.8° 视场内 30 ms 曝光只能记录到 10² 量级的恒星，与 §1.3 的实测数量**独立吻合**——两条互不依赖的推理指向同一结论，这是答辩时的有力论据。
2. 宽视场使盲板求解容易成功（Tycho-2 亮星密度足够），无需深场星表。

注意台站坐标与 `观测信息.txt`（88.57720184, 43.522201, 1790 m）不一致，相差约 0.2°/23 km。设计上以 FITS 头的 `SITELONG`/`SITELATI`/`SITEALTI` 为准（它与图像逐帧绑定），并把这一差异作为已知数据质量问题记录在报告中。该差异只影响 AltAz→ICRS 的指向初值，不影响任何以像素或以 `.DAT` 为基准的结果。

### 1B.2 关键发现五：序列含三个机架状态段

`AZIMUTH` 的逐帧增量把 80 帧清晰划为三段：

| 段 | 帧 | ΔAZ / 帧 | 机架状态 |
|---|---|---|---|
| I | f00–f15 | −6° ~ +6°（跳变） | **搜索/摆扫**，非跟踪 |
| II | **f16–f70** | **+0.222°（极稳定）** | **稳定跟踪** |
| III | f71–f79 | −6°（跳变） | 摆扫收尾 |

第 II 段的 ΔAZ 标准差极小（0.222 ± 0.003°/帧），是明确的跟踪段。

**`.DAT` 的 55 行时间戳与 f16–f70 的 `DATE-OBS` 逐条精确对应，误差 0.0000 s。** 真值只覆盖跟踪段，这独立证实了分段判断。

**设计含义**：流水线必须先做**机架状态分段**，只在跟踪段上运行双坐标系判决。分段判据用 `ΔAZ` 的滚动标准差，不依赖图像。这既是必要步骤，也直接消解了原 §3.4 中"f00–f04 两系皆小无法分离"的遗留问题——那本质上就是非跟踪段，正确做法是识别并排除，而非勉强判决。

### 1B.3 关键发现六：低仰角 + 长基线的两个后果

仰角仅 15°，天球角速度 ≈ ΔAZ × cos(el) ≈ 0.222° × cos 15.6° ≈ 0.214°/帧。

1. **场移约 126 px/帧，全段累计约 6495 px** — 超过 4096 px 的图幅。因此**没有一颗恒星贯穿整个跟踪段**：实测 f16 的 120 颗源中，只有 1 颗在 ≥60% 的帧中出现。
2. **场旋转仅约 0.1°/帧**（低仰角处 alt-az 视场旋转率小），累计 −3.3°。旋转依然必须建模（累计量远超 PSF 尺度），但单帧对的旋转比数据集 A 小。

**对 §3.5 星场叠加的直接影响**：全 55 帧叠加得不到深场——大部分像素只被少数帧覆盖。叠加必须改为**滑动窗口 + 覆盖度图**（见修订后的 §3.5）。这是新数据带来的最重要的设计修正。

### 1B.4 关键发现七：目标已确认，并经真值双重校验

分段后在探测器坐标系中做静止性搜索（4σ 探测、屏蔽热像素、8 px 关联半径），**全序列只有一条轨迹存活**：

- f17–f70，**54 帧连续**
- 起点 (2271.6, 1958.8) → 终点 (2365.8, 1976.3)，探测器系累计漂移 95.8 px（1.81 px/帧）
- flux 264 → 2283，中位 elongation 1.24
- 同期星场移动 126 px/帧 —— 静止性对比度约 70 倍

用 `.DAT` 真值做三项独立校验：

| 校验项 | 结果 | 判断 |
|---|---|---|
| 像元比例尺（DAT 角步长 / 天球系像素步长） | **6.179 ± 0.013 ″/px** | 55 帧一致到 0.2%，且与数据集 A 的独立推导（≈6″/px）吻合 |
| 星等相关性（DAT 星等 vs 仪器星等） | **r = 0.949** | 光度确实来自同一物体 |
| 定标零点 | **15.335 ± 0.218 mag** | 散度 0.22 mag，可用于绝对定标 |

DAT 角步长 776.9 ± 6.3 ″/帧，天球系像素步长 125.73 ± 0.94 px/帧。

**这三项把项目的性质改变了**：此前所有精度声明都只能靠物理自洽性论证，现在可以给出**对真值的定量误差**。§8 测试策略与 §4 比赛映射据此升级。

（一处待查项：DAT 的运动方向角为 128.08°，而天球系轨迹方向角为 −5.66°。像元比例尺、星等相关性、零点三项都自洽，说明目标身份无疑；方向差源于像素坐标系与赤道坐标系之间的定向关系——y 轴翻转加视场旋转角，即一个待定的常量旋转 + 反射。这正是 §5 盲板求解要给出的量，不影响任何以像素或以标量距离为基准的结论。实施时在 P1 阶段用 DAT 拟合出该定向矩阵并回代验证。）

### 2.2 为什么是双坐标系

单一坐标系只能给出一条证据。双坐标系给出两条**互相独立**的证据（下表数值取数据集 B 的实测值）：

| | 探测器坐标系 | 天球坐标系 |
|---|---|---|
| 目标表现 | 静止 (1.8 px/帧) | 快速运动 (126 px/帧) |
| 恒星表现 | 快速拖动 (126 px/帧) | 静止 (< 2 px/帧) |
| 热像素表现 | 静止 (混淆源) | 快速运动 (混淆源) |
| 噪声表现 | 不复现 | 不复现 |

目标与恒星在探测器系中的速度比约 70 倍，判据的裕度极大。

单看任一坐标系，热像素都会与目标混淆。但热像素在**两个**坐标系中的行为与目标完全一致，唯一区别是它锁定在固定像素上且数值恒定——因此以"跨帧数值恒定性"为独立判据即可完全分离（§3.1）。

真实目标必须同时满足：探测器系静止 **且** 天球系运动 **且** 非像素锁定。三条件合取，误报率极低——数据集 B 上 55 帧、约 6000 次源检出，最终只有一条轨迹存活，且被真值确认。

### 2.4 运行环境策略

按用户决定：**CPU 为默认路径，GPU 为可选加速。**

- 全部算法以 numpy / scipy / astropy / photutils 实现，纯 CPU 可完整跑通。
- 背景建模等热点提供 CuPy 后端，运行时探测可用性后自动启用；`import cupy` 失败即静默回退。
- 后端选择在日志中显式记录，两条路径的数值结果一致性由单元测试守卫。

理由：国赛需现场提交并运行程序，评委机器很可能无 CUDA。现有 `gpu_preprocessor.py` 硬依赖 `import cupy`，在无卡机器上直接崩溃——这是可运行性风险，而非亮点。

## 3. 核心模块设计

### 3.0 机架状态分段

**输入**：全序列 FITS 头的 `AZIMUTH` / `ELEVATIO` / `DATE-OBS`。不读像素数据，成本可忽略。

**算法**：对 `ΔAZ/Δt` 序列取长度 5 的滚动标准差，低于阈值（默认 0.05°/帧）且持续 ≥10 帧的区间标记为**稳定跟踪段**。其余标记为摆扫/搜索段。

**实测效果**：数据集 B 上精确切出 f16–f70（55 帧），与 `.DAT` 的 55 行时间戳逐条吻合；数据集 A 上切出 f05–f35。

**为什么必须先做这一步**：
- 双坐标系判决只在跟踪段内成立。非跟踪段星场跳变 6°/帧（约 3400 px），帧间无共同视场，配准无解。
- 分段结果同时是"哪些帧参与叠加"的依据。
- 该判据只用头文件，不依赖任何图像处理，因此绝不会被噪声影响——是整条流水线中最可靠的一步，适合放在最前面。

输出 `output/calib/segments.json`：每段的起止帧、ΔAZ 均值与标准差、状态标签。

### 3.1 热像素识别

**判据**：跨全序列位置固定且数值方差极小的像素。

对全部帧逐像素取时间轴统计量，标记满足 `median > 背景 + 5σ` 且 `(max − min) / median < 0.05` 的像素。目标与恒星因视场移动不可能满足该条件（它们只在少数帧经过某像素）。

**按簇建模**：实测热像素以 2–7 个相邻像素的连通域出现（如 `(244,3174)` 处共 7 个像素），因此对初步掩膜做连通域标记并整簇膨胀 1 px，避免簇边缘残留。

**跨数据集稳定性**：数据集 A 与 B（相隔 4 个月）扫出的簇中心完全相同——`(244,3174)`、`(312,3206)`、`(327,3210)`。这既确证了传感器缺陷的判断，也允许把热像素图作为可复用的定标产物。

输出 `hotpixel_mask.fits` 与 `hotpixel_clusters.json`，在探测阶段前应用。

### 3.2 单帧探测基线

**两档阈值，用途分离**：

| 用途 | 阈值 | 依据 |
|---|---|---|
| 星点计数、星等（对外报数） | **5σ, npixels ≥ 5** | 复现率 90.3%（数据集 A 实测） |
| 目标搜索（内部关联） | **4σ, npixels ≥ 5** | 目标在弱帧 flux 仅 264，需要更低门槛；虚警由时序关联滤除 |

分离的理由：对外报数要求纯度，时序关联本身已提供极强的滤噪能力（55 帧中要求 ≥10 帧连续），可以承受更多单帧虚警以换取对暗目标的完整覆盖。实测 4σ 下目标轨迹长 54 帧，5σ 下会在若干弱帧断裂。

两档阈值都在配置中显式列出，报告中说明各自的适用范围——把"用不同阈值"从可质疑点变成经过论证的设计选择。

背景与 RMS 用 128×128 网格 + sigma-clip 中位数估计，双三次插值放大——延续现有实现的思路（该部分设计本身是合理的）。

PSF 用 2D 高斯 + 常数基线拟合，给出亚像素中心、FWHM、椭率、残差比。这是定位精度的主要来源，保留原规划中的这一正确判断。

### 3.3 配准求解

两阶段，兼顾稳健性与精度：

1. **粗解**：旋转角在 ±1.5° 内以 0.05° 步长扫描，每个角度下对位移做二维直方图投票（4 px 分箱），取票数最高者。已实测在两个数据集上全程稳定收敛。
2. **精解**：以粗解为初值做星点匹配（5 px 半径），对内点用最小二乘拟合相似变换（旋转 + 各向同性缩放 + 平移，4 参数），迭代剔除离群点。

变换模型采用绕视场中心的相似变换。选相似变换而非完整仿射：4 参数比 6 参数在 80 个内点下更稳定，且实测累计尺度因子 0.99822（55 帧后偏离 0.18%），说明无需额外自由度吸收畸变。

**逐帧链式累积**：`M[i+1] = M[i] @ M_pair(i→i+1)`，全部帧映射到跟踪段首帧的坐标系。数据集 B 实测每对内点数 74–93（中位 84），累计变换为尺度 0.99822、旋转 −3.325°、平移 (+6495, −540) px。

**误差累积的处理**：链式累积会累加误差。用两条独立方式监控：
- 像元比例尺的逐帧一致性（数据集 B 实测 6.179 ± 0.013 ″/px，55 帧偏差 0.2%，说明累积误差可接受）
- 对有真值的数据集，直接与 `.DAT` 比对（§8）

若发现漂移超标，降级方案是分块参考（每 10 帧重设一次参考帧，块间再对齐），但目前实测不需要。

**质量门禁**：内点数低于阈值（默认 30）的帧对标记为配准失败，进入降级路径而非静默产出错误结果。实测最低 74，裕度充足。

### 3.4 双坐标系交叉确认

对每个候选源计算两个运动量：
- `v_det`：在探测器坐标系中的逐帧位移
- `v_sky`：应用配准变换后在天球坐标系中的逐帧位移

判决规则（默认阈值如下，均可在 `config/default.yaml` 中调整；括号内为数据集 B 实测值）：

- `v_det` 小：中位帧间位移 < 8 px/帧（目标实测 1.8）
- `v_sky` 大：中位帧间位移 > 30 px/帧（目标实测 126）
- 像素锁定：整数像素位置在全序列不变，且峰值 `(max−min)/median < 0.05`
- 复现：在跟踪段内 ≥10 帧连续被匹配到（目标实测 54 帧）

| 条件 | 判定 |
|---|---|
| `v_det` 小 且 `v_sky` 大 且 非像素锁定 | **空间目标** |
| `v_det` 大 且 `v_sky` 小 | 恒星 |
| `v_det` 小 且 `v_sky` 大 且 像素锁定 | 热像素 |
| 任一坐标系中不复现 | 噪声 |
| 两系皆小 或 两系皆大 | 未分类，进人工复核清单 |

"两系皆小"这一格在跟踪段内不应出现（星场以 126 px/帧 扫过，任何真实源在两系中必有一个是运动的）。它在数据集 A 的 f00–f04 上出现过，原因是那本身不是跟踪段——现由 §3.0 分段前置解决。保留该格作为异常检测：若它在跟踪段内非空，说明分段或配准出了问题，应报警而非静默通过。

每个判定都记录支撑证据（两个速度值、复现帧数、像素锁定标志），供报告与答辩引用。

**实测判别力**：数据集 B 跟踪段 55 帧、约 6000 次源检出，最终只有一条轨迹通过全部条件，且经 `.DAT` 三项校验确认为真实目标（§1B.4）。零虚警、零漏检。

### 3.5 星场叠加（滑动窗口 + 覆盖度图）

原设计假设全部帧共享视场，直接全序列平均得 √N 增益。**数据集 B 证明该假设不成立**：跟踪段累计场移 6495 px > 4096 px 图幅，没有一颗恒星贯穿全段（实测 f16 的 120 颗源中仅 1 颗覆盖 ≥60% 帧）。

修正为**滑动窗口叠加 + 显式覆盖度图**：

1. 以窗口长度 `W`（默认 12 帧，实测场移约 126 px/帧 ⇒ 窗内累计约 1500 px，仍有约 63% 的图幅重叠）滑过跟踪段。
2. 每个窗口内按配准变换重采样到窗口中心帧的坐标系，取加权平均，同时累加**覆盖度图** `N(x,y)`——记录每个输出像素由多少帧贡献。
3. 深度增益按逐像素的 `√N(x,y)` 计算，而非一个全局数字。窗口中心区域 N=12（增益约 3.5 倍，≈1.3 mag），边缘 N 递减。
4. 所有基于叠加图的测量都必须携带该像素的 `N` 值；`N < 4` 的区域标记为不可用。

窗口长度 `W` 是深度与面积的权衡，在配置中暴露；报告中给出 `W` vs 有效面积/深度 的曲线作为参数选择依据。

**诚实报数**：因此本项目**不宣称统一的 +1.9 mag 深度**，而是给出覆盖度加权的深度图。这比报一个不成立的数字更有说服力，也是应对"你的叠加真的有效吗"这一质疑的直接答案。

叠加时以热像素掩膜与逐帧质量权重加权；目标本身在天球系中运动，会在叠加图中被平均掉（这正是期望行为——叠加图用于恒星，不用于目标）。

输出 `output/stack/coadd_w{W}_c{center}.fits` 与配套的 `coverage_*.fits`。

### 3.6 可复现性验证器

这是本项目的**论证基础设施**，不只是测试工具。

给定阈值扫描范围，自动产出"检出数 vs 阈值"与"复现率 vs 阈值"双曲线，即 §1.3 / §1B.5 表格的完整版本。该图直接回答"为什么只报 10² 颗星"这一必然被追问的问题，也是把"别人多报了"从主张变为论证的关键。

**两数据集并列**：曲线在数据集 A 与 B 上分别绘制并叠在同一张图上。两次相隔 4 个月、不同目标、不同仰角的独立观测给出形态一致的阈值曲线，这比单数据集的结论强得多。

### 3.7 真值比对验证器

数据集 B 带 `.DAT`，因此可以给出**对真值的定量误差**，而非仅有物理自洽性论证。

比对项：

| 项 | 方法 | 数据集 B 实测 |
|---|---|---|
| 像元比例尺 | DAT 角步长 / 天球系像素步长，逐帧 | **6.179 ± 0.013 ″/px** (0.2%) |
| 轨迹形状 | 天球系轨迹与 DAT 角轨迹的标度后残差 | 待 P1 定向矩阵求出后给出 |
| 星等 | DAT 星等 vs 仪器星等的相关与零点 | **r = 0.949，零点 15.335 ± 0.218 mag** |
| 时间对应 | DAT 时间戳 vs `DATE-OBS` | **逐条精确对应，误差 0.0000 s** |

`.DAT` 的用途严格限定为**验证**，不作为流水线输入。这一点必须在报告中写明——否则"用真值算出真值"会构成致命的方法论质疑。代码层面通过模块依赖保证：`validate/truth.py` 只被验证与报告环节导入，`detect/` `register/` `target/` 不得引用它。该约束由单元测试守卫（检查导入图）。

输出 `output/<dataset_id>/validation/truth_report.json` 与误差图。数据集无 `.DAT` 时（如数据集 A）本模块跳过，并在报告中标注"无真值可比对"，不产生空文件。

## 4. 比赛内容映射

### 4.1 星图识别（25 分）

两个方向均完成（科学性满分档要求"同时完成了两个方向题目"）。

**星点识别**：在指定单帧上以 5σ 基线给出星点总数（10² 量级），并附：
- 可复现性曲线，论证阈值选择（两数据集并列）
- 与 SExtractor 的交叉匹配诊断，定量说明差异来源
- 滑动窗口叠加图 + 覆盖度图的对照计数

**星等识别**：找出最暗星并标注星等。定标路径见 §5，主路径为基于 `.DAT` 真值的离线零点反推，盲板求解 + 星表匹配作为交叉校验。

**数据集 B 提供的这条独立定标路径**：`.DAT` 给出目标的逐帧真值星等（7.19–8.81 mag），与仪器星等的相关系数 0.949，反推零点 15.335 ± 0.218 mag。用这个零点即可把全场恒星的仪器星等转成绝对星等——**不依赖任何外部星表或网络**。盲板求解因此从"星等定标的必要条件"降级为"交叉验证手段"，风险大幅下降。

若盲板求解与真值定标都失败，降级为仪器星等并显式标注该限制。

### 4.2 星图分析 — 动目标识别（35 分）

主结果：目标的完整轨迹（逐帧亚像素位置、角速度、天球坐标）。数据集 B 上已验证可得 54 帧连续轨迹（f17–f70）。

**关键增强——定量精度声明**：因为有 `.DAT` 真值，可以给出"我们的测量与官方真值的偏差是多少"，而不只是"我们的方法自洽"。像元比例尺 55 帧一致到 0.2%、星等相关 0.949 已经是可直接引用的数字。这是评分表"科学性 20 分"中最难得的东西。

架构上不设"只找一个目标"的假设——双坐标系判决对任意数量目标同等适用。当前两个数据集各含 1 个被跟踪目标；若某帧内出现第二个空间目标（未被跟踪，因此在探测器系中运动），它会落入"两系皆大"格。该格的处理是一项明确的扩展点：对这类源改用线性运动 + 匀速判据识别，作为多目标能力的补充路径。

创新性论证点：双坐标系交叉确认是本方案的原创构造，其出发点（识别出"望远镜在跟踪目标"这一观测配置，并进一步识别出序列含三个机架状态段）本身即为分析成果。

### 4.3 创新赛项（30 分）

满分档要求"4 个及以上创新有效分析数据"。规划如下（均由主流水线的中间产物自然导出，非硬凑）：

1. **系统自标定**：像元比例尺与视场，由机架转动率与实测场移互推得出，无需外部标定源。**三条独立路径互证**：数据集 A 推得 ≈6″/px；数据集 B 由机架率推得同量级；数据集 B 由 `.DAT` 真值标定得 **6.179 ± 0.013 ″/px**。前两条不用真值、第三条用真值，三者吻合。
2. **机架状态自动分段**：仅凭 FITS 头识别搜索段/跟踪段/收尾段，并由 `.DAT` 时间戳的覆盖范围独立确认（55 行 ↔ f16–f70 逐条对应）。这是"从数据反推观测策略"的分析成果。
3. **目标 J2000 轨迹**：赤经赤纬时间序列，**以赛方 `.DAT` 格式输出**（格式取自 `说明文件.txt`），便于与官方真值直接比对。
4. **轨道高度反演**：由角速度反推轨道高度，与目标的公开 TLE 交叉校验（NORAD 60385 / 60394）——实用性分项的有力支撑。
5. **目标光变曲线**：逐帧测光给出光变，用于判断姿态稳定性/自旋周期。数据集 B 的 `.DAT` 真值星等（7.19–8.81 mag，全段变化 1.6 mag）为光变的真实性提供了直接佐证。
6. **传感器健康度**：热像素图与噪声统计，并给出**跨 4 个月两次观测的缺陷位置一致性**——这是单次观测无法得到的结论。
7. **观测条件**：视宁度 (FWHM 统计) 与天光背景亮度 (mag/arcsec²)。

第 4 项对"分析所得数据对现实场景有实际意义"（实用性 10 分）最为直接：轨道高度是太空交通管理的基础量。第 2 与第 6 项是新数据带来的增项，均有交叉验证支撑。

## 5. 星等绝对定标

**三级路径，风险逐级隔离**：

**第一级（无网络、无真值）**：仪器星等 `m_inst = -2.5 log10(flux)`，全流程离线可跑。保证基础分不依赖任何外部条件。

**第二级（真值定标，无网络）**：用数据集 B 的 `.DAT` 真值星等对仪器星等做线性拟合，得零点。实测 **零点 15.335 ± 0.218 mag，相关系数 0.949**（55 个数据点）。零点一旦确定即可施加于全场恒星，给出绝对星等。**这条路径完全离线**，是本设计相比原方案最重要的风险削减。

方法论边界：零点由目标（一个已知天体）定出，施加于恒星时假设两者的光谱响应与大气路径相近。目标仰角 15°、恒星同帧同视场，大气路径差异可忽略；光谱差异（卫星表面反射太阳光 vs 恒星本征光谱）会引入色项误差，这是 0.218 mag 散度的主要来源之一。报告中显式声明该假设，并把它作为与第三级路径交叉验证的动机。

**第三级（增强，需网络）**：
1. 在滑动窗口叠加图上做盲板求解，得到 WCS。初值可由 `AZIMUTH`/`ELEVATIO` + 台站坐标 + 时间换算的指向提供（AltAz→ICRS 已实测可行），把盲搜索收窄为局部匹配。
2. 匹配 Gaia DR3 / Tycho-2 亮星，最小二乘拟合零点，得独立的绝对星等定标。
3. 与第二级的零点比对——两条完全不同来源的定标互证，是强有力的科学性论据。
4. 目标像素坐标经 WCS 转 J2000，产出 §4.3 第 3 项；同时解出 §1B.4 遗留的像素↔赤道定向矩阵。

**降级策略**：第三级失败退第二级，第二级不适用（无真值数据集）退第一级。每级的定标状态在输出中显式标注。基础分不会因增强项失败而丢失。

风险说明：`astroquery` 当前未安装，需加入依赖；星表查询依赖网络（实测容器内 DNS 不通，astropy 连 IERS 表都下载失败）。这是第三级被定为增强项的原因，也是第二级路径价值的体现。

## 6. 数据管理

分级落盘，便于回溯与答辩取证：

```text
output/
├── <dataset_id>/           # 按数据集隔离，A/B 结果不混
│   ├── calib/              # 分段结果、热像素图、背景图、RMS 图
│   ├── detections/         # 逐帧原始检出 (含全部特征与标志位)
│   ├── registration/       # 帧间变换参数与内点统计
│   ├── stack/              # 滑动窗口叠加图 + 覆盖度图
│   ├── catalog/            # 最终星表 / 目标表 / .DAT 轨迹
│   ├── analysis/           # 创新赛项派生量
│   └── validation/         # 可复现性曲线、真值比对报告
└── figures/                # 跨数据集成果图（PPT 素材）
```

数据集按目录隔离是必要的——两个数据集的目标、仰角、机架行为都不同，产物混在一起会导致答辩时取错数字。`<dataset_id>` 取数据包目录名（如 `60385_20260722_1485695076008039_PIC_POS`）。

每个产物附带生成参数与代码版本，保证结果可复现。

## 7. 错误处理

系统面向答辩场景，**宁可显式失败并说明，不可静默产出错误数字**。

| 情形 | 处理 |
|---|---|
| FITS 头非标准（实测 `AZIMUTH` 卡片不合规） | `verify('silentfix')` 后读取，记录修复项 |
| 配准内点不足 | 标记该帧对失败，排除出叠加，报告中列明 |
| PSF 拟合不收敛 | 保留质心结果，置 `psf_fit_failed` 标志，不参与精度统计 |
| CuPy 不可用 | 静默回退 CPU，日志记录后端 |
| 星表查询失败 | 降级为仪器星等，报告标注定标状态 |
| 目标数为 0 | 明确报告"未检出"，不放宽阈值凑结果 |

## 8. 测试策略

| 层级 | 内容 |
|---|---|
| 单元 | 分段判据（合成 ΔAZ 序列）；配准变换的正确性（合成已知旋转+平移+缩放，验证求解精度）；PSF 拟合（合成已知高斯，验证亚像素误差）；热像素判据与成簇；星等公式；`.DAT` 读写往返一致性 |
| 依赖约束 | 检查导入图，确认 `detect/` `register/` `target/` 不引用 `validate/truth.py`（防止真值泄漏进流水线） |
| 后端一致性 | CPU 与 GPU 背景建模结果在容差内一致 |
| 集成 | 全流水线在两个真实数据集（36 帧 / 80 帧）上跑通，产出全部分级产物 |
| 回归 | 关键数字纳入基线快照：分段边界 f16–f70、轨迹长度 54 帧、像元比例尺 6.179 ″/px、零点 15.335 mag、星等相关 0.949。任何改动导致这些数字偏移即失败 |
| **真值验收** | 与 `.DAT` 比对：像元比例尺相对误差 < 1%、星等相关系数 > 0.9、时间戳对应误差 = 0。这是硬性通过标准，不是参考指标 |
| 物理自洽 | 像元比例尺的三条独立推导路径互相校验；轨道高度与公开 TLE 比对 |
| 跨数据集 | 在数据集 A 上重跑，确认阈值曲线形态、热像素位置、分段逻辑一致——防止参数被单一数据集过拟合 |

真值验收这一层是新数据带来的最大收益：它把"我们的方法自洽"升级为"我们的结果对得上官方真值"。合成数据测试仍然保留，用于验证在真值无法覆盖的环节（如恒星的亚像素定位精度——`.DAT` 只给目标的真值）的精度。

## 9. 与原规划的差异说明

`规划.md` 中以下判断经实测确认正确并予保留：
- PSF 拟合是单帧精度的主要来源
- 阈值应基于局部 RMS 而非全局固定值
- 多帧信息比单帧更可信
- 物理约束优先于经验规则
- 所有模块应可量化评估

以下需要修正：

| 原设计 | 问题 | 修正 |
|---|---|---|
| `speed < 0.5 → STAR` | 本数据集下方向相反 | 双坐标系判决 |
| 候选生成"宁可多报不可漏报"，2.0–3.0σ | 实测 90% 虚警，与"数据准确"冲突 | 5σ 报数基线 + 4σ 搜索基线 + 可复现性论证 |
| 无热像素处理 | 会被误判为高置信目标 | 热像素图前置剔除（按簇） |
| 单帧独立处理 | 30 ms 曝光过浅，无法支撑星等工作 | 运动补偿叠加 |
| GPU 为主路径 | 评委机器可能无 CUDA | CPU 默认，GPU 可选 |
| 以 SExtractor 为标准基准 | 其默认参数在本数据上同样虚警主导 | 改为交叉匹配诊断工具，非真值 |
| 全序列统一处理 | 序列含非跟踪段，配准无解 | 机架状态分段前置（§3.0） |
| 全帧叠加得 +1.9 mag | 场移超图幅，无恒星贯穿全段 | 滑动窗口叠加 + 覆盖度图（§3.5） |

关于 SExtractor 的定位调整值得强调：它仍然有用，但用途从"基准真值"变为"差异诊断对象"。`规划.md` 附录中关于交叉匹配"验尸"的思路是对的，本设计将其制度化为 §3.6 的验证器。

后两项修正来自数据集 B——它们是本轮设计修订的实质内容，也说明"先做数据事实核查再定架构"这一做法本身的价值。

## 10. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| 两个数据集各 1 目标，题面要求 15 图 | 无法完全覆盖原始题面 | 用户补全数据；架构不假设目标数量与帧数，按数据集目录批量处理 |
| 数据集 B 站址坐标三处不一致（`观测信息.txt` vs FITS 头） | AltAz→ICRS 初值偏差 | 以 FITS 头为准并记录差异；该初值只用于盲板求解引导，不进入判决链 |
| 像元↔赤道坐标定向未定（DAT 方位角 128.08° vs 天球系路径 −5.66°） | J2000 轨迹产出受阻 | P1 从 `.DAT` 拟合定向矩阵（旋转+反射）后回代；比例尺/星等/时标三项已自洽，目标身份不受影响 |
| 盲板求解可能失败（容器内无网络，IERS 亦降级） | 绝对星等定标受影响 | 已有离线真值定标路径（§3.7）作为主路径，盲板求解降为交叉校验 |
| 星点数 ~10² 与直觉不符 | 可能被质疑"漏检" | 可复现性曲线 + 视场/曝光独立推导 + SExtractor 差异诊断 |
| 参数被单一数据集过拟合 | 换数据即失效 | 两数据集互为对照（阈值曲线、热像素位置、分段逻辑），纳入测试 |
| 评委机器无 GPU | 程序无法运行 | CPU 默认路径 |

倒数第三项风险的处理方式，也是本设计把"星点数偏少"从弱点转为亮点的方式：主动、定量、多路径地论证这个数字为何正确，比报一个大数字更能体现科学性。

数据集 B 带来 `.DAT` 真值，消除了原登记表中"无真值"这一条最重的风险——精度论证从"物理自洽"升级为"对官方真值定量核验"。
