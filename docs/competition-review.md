# 比赛要求核查与本次修订

依据：项目 `chores/` 中《B02-仿真技术赛道-太空目标识别仿真组比赛规则及评审（裁判）标准》
（2026 年 3 月），以及用户补充的源码 ZIP ≤200 MB 要求。比赛原文作为评审依据；
本记录不把评审要求解释为已验证的成绩。下表保留此前地基交付核查，新增官方天基
运行结果见下方更新和 `docs/reports/rst19-2026-09-23.md`。

| 要求 | 本次修订或现状 | 仍需注意 |
|---|---|---|
| 指定单张图像的星点识别与数量 | CLI 可指定帧号，分别输出去坏点探测数、跨帧确认候选数，附逐源 CSV | 计数是给定阈值下的保守结果，未做注入回收，不能称为找全所有星点 |
| 找出最暗恒星并标注星等 | 新增实际候选选取、位置标注与放大图；至少 4/6 帧互为最近邻确认，排除单帧噪声与截断孔径 | 候选集内的最暗者；缺定标时明确只报仪器星等；真值波段未指定，不能称为标准 V 星等 |
| 多运动目标识别 | 底层支持多条轨迹，CLI 全部编号导出，不再只展示 `[0]` | 两目标合成测试通过；现有 B 数据实测只有 1 个，不把它写成多个真实目标验证 |
| 科学性、无原理冲突 | 修正第 30 帧图片使用第 70 帧目标位置的错误；热像素标注与实际筛除一致；真值流量按帧号对齐 | 高度为圆轨道自相容区间；无 WCS 不输出赤经赤纬；待提供对应历元 TLE 后才能做外部轨道对照 |
| 星等计算一致性 | 新入口用相同固定孔径测量恒星和目标，统一按曝光归一到 ADU/s 后拟合零点 | 历史教程仍用于复现旧指标，旧分割流量零点与新孔径零点不可混用 |
| ≥4 类创新分析数据 | 既有角速度、高度区间、传感器缺陷、观测条件四类结果保留 | 后两种角尺度/天光量依赖真值定标；结果类别数不保证创新性分数，也不证明领域内无类似工作 |
| 国赛交运行程序与源代码 | 新增 Windows 入口、可重建 CPU 镜像、CSV/JSON 输出、源码白名单打包与 200 MB 上限校验 | 数据和镜像单独提供；源码 ZIP 本身不是完整离线演示环境 |
| PPT≤100 MB、MP4≤100 MB且≤3分钟 | 规则已记录，新入口实跑约 144 秒 | 本轮没有新制作视频或 PPT，最终文件仍应单独核验 |

## 官方天基数据适配（2026-09-23 更新）

用户现已提供 `data/rst19/` 的 15 张官方天基图像及格式说明。程序新增独立天基分支，
不套用地基机架跟踪判据；读取首行姿态/轨道辅助数据，检测前排除首行和异常像素，
在配准后的星场中寻找多帧运动，并用曝光拖尾方向、长度核验候选。

指定 f7 实测 12,842 个跨帧点状候选、26 条运动候选。Gaia DR3 提供独立的星表定标，
最暗候选为 G 参照估计约 14.53 等；不称为标准 V 星等。详情与来源见
`docs/reports/rst19-2026-09-23.md`。本次仍未证明探测完备性，26 条是通过所述判据的
候选轨迹数，不是有真值保证的目标总数；单帧高速拖尾、少于 4 帧和更弱的目标可能漏检。

## 结论的表述

可以陈述：官方天基序列通过多帧与拖尾形态判据得到 26 条运动候选；在指定帧按明确
阈值报告恒星候选，并给出最暗候选的位置及 Gaia G 参照星等估计。历史地基数据仍独立
保留，不和天基结果混用。

避免陈述：已经找全图中所有恒星；95 百分位等于最暗恒星；现有单目标实测证明天基
多目标识别；真值定标量是独立验证真值的证据；没有真实 TLE 却称轨道吻合。
